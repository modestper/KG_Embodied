### 任务背景

用户希望自己设置 Neo4j 查询语句，用来测量知识图谱查询时间开销，因此需要了解是否有论文研究查询语句、查询工作负载和图数据库基准设计。

### 关键结论

- 查询语句不应该只随机写几条，而应覆盖不同查询形状：点查、星型、多跳链式、雪花型、复杂 join、路径查询、聚合排序、时间窗口、读写混合。
- WatDiv 强调用结构特征和选择性差异设计 SPARQL 查询，包含 linear、star、snowflake、complex 查询模板。
- LDBC SNB 区分交互式邻域查询和 BI 类大范围聚合 join 查询，适合参考到 Neo4j/Cypher。
- FEASIBLE 和 LSQ 更偏“从真实查询日志中选代表性查询”，适合后续你们从 agent 的真实查询日志中抽样。
- gMark 研究可控图和查询生成，特别关注 regular path queries 和选择性估计。
- FinBench 很适合参考时间窗口、路径过滤、热点节点、高并发读写混合这些更接近业务系统的压力点。

### 执行过的操作

- 搜索并阅读了 WatDiv、LDBC SNB、FEASIBLE、LSQ、gMark、FinBench、IGUANA 等相关论文/项目页面。

  - WatDiv 查询模板分类和选择性设计。

  - FEASIBLE 基于 query log 和查询特征筛选 benchmark。
  - LSQ 查询日志数据集及 benchmark 用途。
  - gMark 可控图和查询工作负载生成。
  - FinBench choke point-driven workload。
  - IGUANA 并发用户、读写混合和 per-query 指标记录。

### 后续建议

- 第一版压测查询建议先覆盖 8-12 个 Cypher 模板，每个模板按低/中/高选择性准备参数。
- 每条查询都记录 `run_id`、模板名、参数、返回行数、延迟、是否失败、并发 agent id。
- 后续可以从 agent 实际查询日志中统计高频模式，再参考 FEASIBLE/LSQ 的方法筛选代表性查询集。
