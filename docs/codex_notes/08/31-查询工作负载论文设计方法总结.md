### 任务背景

用户希望进一步理解前面提到的 WatDiv、LDBC SNB、FEASIBLE、LSQ、gMark、FinBench 等论文或基准分别推荐如何设计查询语句，以便更全面地覆盖 Neo4j/Cypher 查询时间开销测试场景。

### 关键结论

- WatDiv 的核心是按查询形状和选择性覆盖，包括 linear、star、snowflake、complex，以及不同选择性来源。
- LDBC SNB 的核心是把工作负载分成短事务读、复杂邻域读、更新、BI 聚合 join 等类别，并用 choke point 方法覆盖优化器和执行引擎瓶颈。
- FEASIBLE 的核心是从真实查询日志中按结构特征筛选代表性查询，而不是人工随机挑选。
- LSQ 的核心是先收集真实查询日志，再用查询元数据和运行时元数据分析真实查询分布，适合后期用 agent 查询日志反向生成 benchmark。
- gMark 的核心是可控生成图和查询，尤其适合设计不同路径长度、正则路径、选择性的查询组合。
- FinBench 的核心是面向业务场景设计图查询，覆盖时间窗口、热点节点、路径过滤、读写混合、边多重性和事务竞争。
- 对当前 LaDe/Neo4j 项目，推荐最终形成一套 LaDe-Cypher benchmark，覆盖点查、时间窗口、单 agent 轨迹、多跳关联、聚合统计、Top-K、路径查询、读写混合和并发混合。

### 后续建议

- 第一版 LaDe-Cypher benchmark 建议设计 10-12 个查询模板。
- 每个模板至少准备低、中、高三档选择性参数，例如小时间窗口、一天中等窗口、全 run 大窗口。
- 并发测试不要只让 100 个 agent 执行同一条查询，应按比例混合点查、轨迹查询、聚合查询、路径查询。
- 后续系统真实运行后，应记录 agent 实际发出的 Cypher 查询日志，再参考 FEASIBLE/LSQ 方法筛选真实代表性查询集。
