- 当前主链路是 LaDe delivery CSV -> Python 仿真环境 -> SSE 动态推流或静态 trace -> 前端页面可视化。
- `simulation/` 是核心业务层；`scripts/run_dynamic_sim.py` 是动态服务入口；`scripts/build_delivery_sim.py` 是离线 trace 入口。
- 没有发现可以直接删除的核心 `.py` 文件；多数脚本虽然不是主服务运行时依赖，但有测试、文档或手动实验用途。

- 最明显的代码级冗余是 `simulation/delivery_sim.py` 中的 `_unused_property_placeholder()`，函数名和引用搜索都表明它是遗留占位。
- `bash/pretty_json.sh` 和 `bash/time_neo4j_query.sh` 是硬编码参数的手动快捷脚本，不是主链路依赖，后续可考虑替换为文档命令或参数化脚本。

### 当前代码结构

项目可以按 6 层理解：

1. 顶层启动入口

- `run_local_sim.sh`：启动本地单进程动态仿真。
- `run_ray_sim.sh`：启动 Ray 并行动态仿真。
- `generate_res.sh`：离线生成静态 trace。
- `run_in_lade.sh`：进入 `lade` conda 环境后执行命令。

2. 后端仿真核心

- `simulation/delivery_sim.py`：任务、无人机、本地仿真循环、规则拍卖派单。
- `simulation/planner.py`：规则成本函数、LLM 单任务 planner、区域级 LLM coordinator。
- `simulation/knowledge.py`：内存事件存储和 Neo4j 知识图谱写入/查询。
- `simulation/ray_delivery_sim.py`：Ray actor 版本仿真环境。

3. 后端工具脚本

- `scripts/run_dynamic_sim.py`：HTTP + SSE 动态仿真服务。
- `scripts/build_delivery_sim.py`：离线仿真并生成 `data/delivery_sim_*.json`。
- `scripts/build_trace_index.py`：扫描 trace JSON 并生成 `data/traces.json`。
- `scripts/build_summary.py`：扫描原始 LaDe 数据并生成 `data/summary.json`。
- `scripts/build_region_boundaries.py`：生成 `data/region_boundaries.json`。
- `scripts/build_region_partition_preview.py`：生成区域划分预览 HTML。
- `scripts/pretty_json.py`：格式化 JSON/JSONL。
- `scripts/query_neo4j.py`：Neo4j 概览查询。
- `scripts/timed_neo4j_query.py`：Neo4j 单条/预设查询计时。
- `scripts/concurrent_neo4j_query.py`：Neo4j 并发查询压测。
- `scripts/build_neo4j_scale_dataset.py`：构造百万级 Neo4j 压测数据。

4. 前端页面

- `index.html` + `src/app.mjs` + `src/data.mjs`：LaDe 数据集概览，读取 `data/summary.json`。
- `simulation.html` + `src/simulation_app.mjs`：静态 trace 回放，读取 `data/traces.json` 和 `data/delivery_sim_*.json`。
- `dynamic.html` + `src/dynamic_app.mjs` + `src/dynamic_regions.mjs`：动态仿真页面，通过 `/events` SSE 接收实时帧。
- `src/styles.css`：三类页面共享样式。

5. 测试

- `tests/*.py`：覆盖仿真核心、Ray、KG、Neo4j 工具、数据构建脚本。
- `tests/*.test.mjs`：覆盖前端数据 helper 和动态区域 helper。

6. 数据、文档和生成物

- `data/summary.json`、`data/traces.json`、`data/region_boundaries.json` 是页面或服务实际会读取的生成数据。
- `data/llm_logs/`、`data/neo4j_*` 是实验日志/压测结果。
- `docs/codex_notes/`、`HANDOFF.md`、`新同学上手阅读指南.md`、`KNOWLEDGE_GRAPH_AND_LLM.md` 是项目说明和交接文档。

### 冗余或疑似冗余

#### 明确重复

1. `migrate.py` 与 `codex_history.py`

- `cmp -s migrate.py codex_history.py` 返回一致。
- `sha256sum` 两者都是 `3f8429feb7e2ddb4292d9089e03215577ff14990804f1d87042e0f21f3b3ea2c`。
- 两者都不是 LaDe 仿真、前端、Neo4j 压测主链路的一部分。
- 建议保留一个名字作为正式入口，另一个移入归档或删除；删除前先确认是否还有外部习惯命令依赖。

#### 代码级冗余

1. `simulation/delivery_sim.py` 中 `_unused_property_placeholder()`

- 函数定义后没有引用。
- 实际属性是通过下面两行动态挂载：
  - `DeliveryTask.pickup_position = property(...)`
  - `DeliveryTask.dropoff_position = property(...)`
- 可以后续直接删除这个占位函数，或者把两个 property 改成 `DeliveryTask` dataclass 内部的正式 `@property`。

#### 手动快捷脚本，疑似可清理

1. `bash/pretty_json.sh`

- 内部硬编码了某个旧 LLM 日志路径和输出路径。
- 真正通用能力在 `scripts/pretty_json.py`。
- 如果不是常用命令，建议删除或改成接收参数的包装脚本。

2. `bash/time_neo4j_query.sh`

- 只固定执行 `run-summary` 和 `jilin-0925-ray001`。
- 真正通用能力在 `scripts/timed_neo4j_query.py`。
- 如果该 run 已不是常用基准，建议转成文档命令或参数化。

#### 字段级预留/兼容，不建议直接删

1. `failure_mode`、`takeover_mode`

- 当前只是被 payload、snapshot、前端展示链路传递，没有实际故障/接管行为。
- 文档中明确说是第二阶段预留字段。
- 不属于文件冗余；除非确定不做故障接管实验，否则不要删。

2. `battery_range_m`

- 旧电池字段，当前核心逻辑使用 `battery_capacity_m`、`battery_remaining_m`、`low_battery_threshold_m`、`safety_buffer_m`。
- 仍在 `RuleBasedPlanner` 兼容分支、Ray payload、Neo4j 写入中出现。
- 可后续标记 deprecated，但不建议现在直接删。

3. `LLMPlanner`

- 动态页面默认启用 LLM 时主要走 `RegionLLMCoordinator`，不是 `LLMPlanner`。
- 但 `LLMPlanner` 可通过 `DRONE_PLANNER=llm` 启用，并且有测试覆盖。
- 不应按“未使用”删除。
