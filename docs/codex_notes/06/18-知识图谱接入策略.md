### 任务背景

用户想了解当前项目接入知识图谱的策略：知识图谱后端如何选择，会保存哪些信息，以及哪些信息会被共享到知识图谱、LLM 或页面中。

### 关键结论

- 当前默认知识图谱后端是 `memory`，也就是 `TemporalKnowledgeStore.events` 内存事件列表；只有设置 `KG_BACKEND=neo4j` 或 `KG_BACKEND=graph` 时才会写入 Neo4j。
- 默认内存 KG 只长期保存两类事件：`task_assigned` 和 `task_completed`，不保存完整 Task、Drone、Region 实体图。
- Neo4j 后端会在保留内存事件的同时，把 `Region`、`Drone`、`Task`、`Event` 节点和相关关系写入图数据库。
- 给区域 LLM 调度共享的 KG 信息只包含同一区域、最近 30 分钟窗口内的 `recent_agent_performance` 和 `recent_events`。
- LLM prompt 还会包含当前批次任务和无人机摘要，例如任务 deadline/dropoff/distance、无人机位置/队列/完成数等；这些不一定都来自 KG，而是调度时从当前仿真对象临时生成。
- 动态 SSE 每帧会向前端发最近 KG 事件和最近 LLM 调用；LLM 调用对象包含完整 request/response/decisions/error，因此开启 LLM 时页面和 JSONL 日志会暴露 prompt 中的任务、无人机和 KG 上下文。
- 当前 KG 不做跨运行共享；内存后端随仿真进程结束丢失，Neo4j 后端可以跨运行保留写入的图数据。

### 后续建议

- 如果要把当前实现升级为严格意义上的知识图谱，需要明确实体、关系、属性更新策略、跨运行隔离策略和清理策略。
- 如果 LLM 日志或前端页面会在多人环境中使用，建议对 `llm_events.request`、`llm_events.response` 和 JSONL 日志做脱敏或摘要化。
- 如果 Neo4j 用于长期实验积累，建议增加 run/session 标识，避免不同实验的数据混在同一批节点关系里。
- 如果希望“哪些信息能共享给 KG/LLM”可配置，建议增加字段白名单或隐私等级配置。
