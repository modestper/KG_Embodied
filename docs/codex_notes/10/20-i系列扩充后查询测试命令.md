### 关键结论

- 原命令的参数格式仍兼容，可以继续用这个脚本进行查询测试；新增查询参数均有默认值，不要求为运行 all 补传新参数。
- `--queries all` 现在表示 `i0-i55` 共 56 条。100 个 drone × 20 次重复 = 2000 个 context；完整调度将执行 112000 次模板查询，原先 12 条时是 24000 次。
- `--max-workers 100` 并发的是最多 100 个 context，每个 context 内 56 条查询按顺序执行；连接池上限 100 不代表服务端一定能同时无等待地执行 100 条查询。
- 正式运行未给 `--time-minute`，且环境没有预设 `KG_TIME_MINUTE` 时，会先从指定 run 的 Step 2300 自动读取时间。step、time 参数不会因 repeat 自动推进。
- 建议先单 drone、all、repeat=1 核对功能和返回结果，再执行完整混合压测；真实决策工作负载也可分别测试 decision、request_help、energy_safety 等情景包。
- 使用新的独立输出路径，避免将旧 12 条实验与新 56 条实验混在一起；两个 JSONL 追加写入，summary JSON 覆盖写入。
- 文件名 `index_query_logs.jsonl` 不会启用索引。按项目部署记录，57687 对应 lade 基线库，61687 对应 lade-index 实验索引库；具体分组应以实际连接和 SHOW INDEXES 为准。
- 本次仅核对代码并做无数据库连接的参数校验，没有启动 100 并发压测或写入用户指定的 test 输出文件。

### 一、原命令的实际含义

| 参数/变量 | 扩充后的含义 |
| --- | --- |
| `DRONE_IDS` 两行 | 构造 `drone-1,...,drone-100`，去掉末尾逗号；原写法正确 |
| `NEO4J_URI=bolt://127.0.0.1:57687` | 实际查询这个 Neo4j 实例，与日志文件名无关 |

| `--step-index 2300` | 快照查询使用的目标上界；具体模板可能回退到更早的已有状态 |
| `--queries all` | 选中 56 条 i 查询，每个 context 执行一遍 |
| `--repeat 20` | 为每个 drone 生成 20 个 context，使用相同 step/time 参数 |
| `--max-workers 100` | 最多 100 个 context 执行任务并发，包内查询串行 |
| `--max-connection-pool-size 100` | Driver 的最大连接池大小 |
| `--query-log-jsonl` | 每条模板查询一条记录，包含耗时、成功/失败、参数、行数和 scope |
| `--context-jsonl` | 每个 context 保存一份所有选中查询的实际结果及指标 |
| `--summary-json` | 保存本次运行的汇总 |

```text
context 数 = 100 × 20 = 2000
模板查询次数 = 2000 × 56 = 112000
```

主函数在需要时还会先做一次 Step 时间辅助读取，该读取不计入模板查询条数。上述数量假设进程完成全部调度；缺 Step、连接失败或进程中断可能使其提前结束。

all 包含当前任务、电量、局部态势、历史事件、反馈和就绪检查，整包耗时与日志体积会随新增工作量增加。单条延迟仍应按 query_id 查看，整包用 context_avg_ms/context_p95_ms 查看；不能将新 all 总耗时与旧 12 条 all 总耗时直接当成相同负载的性能对比。

### 三、step 2300 与当前态查询的边界

命令可以执行，但 all 不是“所有结果都还原成 step 2300 当时状态”。

- snapshot 查询按不晚于 step 2300 的历史 AgentState/Step 读取。
- event_window 查询按解析得到的 time_minute 限制事件上界。
- current 查询读取 Drone/Task/关系当前属性，数据库若已推进到更后面，这些属性也已经更新。

`temporal_scope` 用于解释这个差别，并没有给 Task 增加历史版本。如果目标是查询压测，固定 step 是一种参数选择；如果目标是重放当时一整次正确决策，则还需解决当前属性与历史状态混合的问题。

如需真正的最新实时上下文，应先确定最新、完整可读的 Step，再以其时间配合当前态查询；本次没有自动改写用户的 step，也没有修改脚本。

`test/index_query_logs.jsonl` 中的 index 只是文件名。创建索引、查询是否使用索引，均由目标数据库和执行计划决定。
