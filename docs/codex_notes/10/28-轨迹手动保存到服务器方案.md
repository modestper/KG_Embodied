# 轨迹手动保存到服务器方案

日期：2026-10-28

### 任务背景

用户希望从刚结束的实时模拟中保存轨迹，保存动作由用户主动触发，并能选择目标文件夹。用户已明确将保存位置改为模拟服务器。本轮结合当前代码确认可行性和接入方式，未实现保存功能。

本方案替代此前《模拟结束后手动保存轨迹方案》中关于浏览器本地另存为、浏览器目录选择器和打开本地文件的建议。范围为网页发起的实时模拟，不包含无头模拟历史数据恢复。

### 关键结论

- 可以实现，属于中等规模的前后端改动。现有模拟已经生成逐步快照，无需重新执行模拟，也无需重新计算无人机路线。
- Local 和 Ray 环境在实时运行中都将每步快照追加到 `env.frames`，并已有 `to_trace()`。服务端可以保留完整轨迹，不必受 SSE 推送采样间隔限制。
- 当前实时服务没有轨迹保存接口，且请求结束会清理活动环境。因此需在结束通知前保留独立的轨迹数据，不能在稍后的保存请求里再读取已经清理的活动环境。
- 用户主动点击保存后才写入轨迹文件；结束时暂存内存数据不等于自动保存文件。尚未保存的数据在服务重启后不能保证保留。
- 服务器目录选择应通过网页列出服务端允许的目录。浏览器的系统文件选择器选择的是用户电脑上的位置，不能用于选择远程服务器目录。
- 保存成功后同步更新轨迹索引，即可接入现有回放页。当前索引仅扫描 `data/` 顶层，需要扩展子目录支持。
- 已结束且环境已经清理的旧运行，没有现成的完整轨迹提取接口；新增功能不能承诺直接追回旧数据。

#### 建议的用户流程

1. 模拟运行期间，“保存本次轨迹”按钮不可用。
2. 模拟正常结束后启用按钮；包括全部任务完成，以及达到最大步数两种情况，并如实保存结束原因和未完成任务数。
3. 用户点击按钮，在网页对话框中选择服务器目标文件夹并填写文件名。
4. 用户确认后，后端写入本次运行的 JSON，并更新轨迹索引；取消则不写入。
5. 页面显示保存结果、服务器路径，并提供“打开回放”入口。

建议将可选目录默认限制在 `viewer/data/traces/` 下，例如按实验名称或日期建立子目录。该目录是建议默认值，本轮没有创建目录或设置实际存储位置。若以后需要其他位置，可由服务启动参数指定允许的根目录。

#### 需要补齐的后端能力

`scripts/run_dynamic_sim.py` 当前负责 SSE 推送、图谱查询和静态文件，没有轨迹保存 API。

建议增加两类接口，具体路由在实现时确定：

- 查询允许的保存目录，返回相对目录列表。
- 保存指定运行的轨迹，请求携带运行标识、相对目录和文件名。

运行完成后，应在发送 `done` 前取得 `env.to_trace()`，补充 `config`、`depots`、区域信息、结束原因、总步数和运行标识，并暂存在独立的完成运行缓存中。缓存只保留数据，不因等待保存而继续占用 Ray actor 或数据库连接；原有环境清理仍需执行。

前端的保存请求应携带这一运行的唯一标识，避免新运行开始后误存其他运行。应明确缓存的数量或容量上限，以及何时失效；失效后显示不能继续保存，不应悄悄改存另一场运行。

已有完整 `env.frames` 可包含最后一步，即使 SSE 的 `frame_stride` 大于 1，也无需用前端采样数据补算完整轨迹。保存时保留真实 Step 信息，使其与图谱中的步数一致。不能把采样后的数组位置当成实际 Step。

文件名建议包含城市、运行时间和运行标识，默认不覆盖已有轨迹。写入使用临时文件和原子提交，成功后再更新索引；失败时向用户返回可理解的错误。目录处理应解析实际路径并确保处于允许根目录内，包括处理 `..` 和符号链接，防止写到错误位置。

大轨迹应逐段或流式序列化到文件，避免先构造一份巨大 JSON 字符串。更新索引可直接根据已知轨迹元数据新增条目，不必每次保存都重新解析所有大型轨迹文件。

#### 与现有回放的衔接

`scripts/build_trace_index.py` 当前使用 `DATA_DIR.glob("*.json")`，只索引顶层文件，且条目的 `file` 只有文件名。应使新保存的子目录轨迹使用相对于 `data/` 的路径，并使索引重建脚本同样支持新目录，同时保留已有顶层轨迹条目。

`src/simulation_app.mjs` 从 `data/traces.json` 读取列表，再拼接文件地址。加载逻辑需要明确支持相对目录路径和逐段 URL 编码；保存成功后的“打开回放”链接可继续使用现有 `trace` 查询参数。

此方案无需新增浏览器本地文件导入功能。回放页重新获取更新后的索引即可看到新增轨迹；实现时也应处理索引缓存，避免保存成功后列表仍显示旧内容。

#### 对刚跑完的旧模拟的说明

当前版本在 `handle_events()` 的 `finally` 中调用 `clear_active_env(env)`，结束后没有持久的完成运行缓存。即使页面仍能回看，其时间轴也只包含实际收到的帧，可能经过采样。

因此本方案实现后，应通过新发起的模拟验证完整服务端保存流程。如果另行要求挽救当前旧页面中的数据，可以评估导出前端现存的采样轨迹，但不能将其描述为服务端保留的完整逐步轨迹。

### 执行过的操作

- 使用 `git status --short` 核对工作区现状。
- 阅读 `AGENTS.md` 和此前的本地保存方案。
- 使用 `rg`、`sed`、`cat` 阅读以下关键模块：
  - `scripts/run_dynamic_sim.py`：SSE 生成、结束通知、HTTP 接口和环境清理。
  - `simulation/delivery_sim.py`、`simulation/ray_delivery_sim.py`：逐步帧保留和 `to_trace()`。
  - `scripts/build_delivery_sim.py`：现有离线轨迹结构和输出约定。
  - `scripts/build_trace_index.py`：轨迹列表生成方式。
  - `src/dynamic_app.mjs`、`src/dynamic_timeline.mjs`：前端时间轴和结束状态。
  - `src/simulation_app.mjs`：轨迹列表和文件加载。
- 未启动模拟、访问 `/events`、查询数据库或重启服务。
- 本轮只做代码核查和文档整理，没有运行功能测试。

### 修改内容

仅新增本方案文档，未修改前后端功能、运行配置或已有轨迹文件。

| 文件或模块 | 主要修改 |

### 后续建议

- 按“结束后保留数据 → 用户选择服务器文件夹并主动保存 → 自动加入回放列表”的流程实现。
- 默认允许在专用轨迹根目录内选择子文件夹，保留现有轨迹和实验结果。
- 实现验证使用隔离的模拟和临时目录，避免干扰正在运行的服务；本轮没有执行功能实现或部署。
