# 仿真状态存储与主进程获取机制

### 任务背景

说明当前项目中的任务、无人机、历史事件与快照分别保存在什么位置，以及主进程如何获得用于调度的状态。本次依据当前源码核对，不修改业务实现、不启动服务。

### 关键结论

- 当前执行状态首先存在 Python 进程内存中。任务由主进程的 `env.tasks` 维护；本地模式的无人机对象也由该进程持有。
- Ray 模式中，每个 actor 内的 `self.drone` 保存该无人机的执行状态；主进程通过远程调用取得快照，构建 `DroneStateProxy` 供调度使用。
- Ray 的任务载荷会序列化与重建，actor 和主进程中的任务是不同对象；通过任务 ID、分配结果、取货/完成事件等显式同步。
- Neo4j 接收实体更新、事件、Step 和可选 AgentState，承担持久化及历史查询。正常派单获取实时位置、电量和队列的入口是运行内存及 actor 快照。
- headless 检查点把可恢复状态保存到本地 JSON；前端帧缓存和离线 trace 用于展示回放，职责不同于恢复检查点。
- 状态获取是仿真步驱动的：主进程请求 actor 执行，等待本轮结果，再汇总下一轮决策所需状态。

### 一、状态保存在哪里

| 状态 | 当前内存位置 | 更新者 | 持久化或展示副本 |
|---|---|---|---|
| 全局任务列表与进度 | 主进程 `env.tasks` 中的 `DeliveryTask` | 本地对象直接更新；Ray 模式合并 actor 结果 | Neo4j Task/Event、检查点、展示帧 |
| 本地无人机位置、电量、队列、载货 | 主进程 `env.drones` 中的 `DroneAgent` | `assign()`、`step()`、互助逻辑 | Neo4j Drone、可选 AgentState、展示帧 |
| Ray 无人机执行状态 | actor 进程 `_DroneActor.self.drone` | actor 内的 `DroneAgent` | actor 返回快照、检查点、Neo4j |
| Ray 调度用无人机状态 | 主进程 `env.drones` 中的 `DroneStateProxy` | snapshot 与 step 结果转成代理 | 被用来构建帧和记录数据库状态 |
| 仿真时间 | 环境的 `env.now_minute` | 环境按步推进 | Step、检查点、帧 |
| 近期与历史事件 | 主进程 `knowledge_store.events` | 派单、取货、完成、充电、互助记录方法 | Neo4j Event；LLM 模式按配置读取历史 |
| 全局步摘要 | 主进程 `knowledge_store.steps` | `record_step()` | Neo4j Step |
| 可恢复运行状态 | headless 的检查点对象及本地文件 | headless 检查点保存钩子 | 默认 `data/checkpoints/<run_id>.json`，可覆盖路径 |
| 页面显示历史 | 普通模式 `env.frames`、浏览器 `FrameTimeline` | 环境生成帧，SSE 推给浏览器 | 离线 trace JSON |

这里的位置、电量和完成状态由仿真代码计算，例如按速度、时间步和移动距离更新。

### 二、本地模式：直接读取同一进程中的对象

`SimulationEnv.__init__()` 保存 `self.tasks` 和 `self.drones`。这些列表中的对象包含当前业务状态：

```python
task.status
task.assigned_to
task.picked_up
task.completed_at

drone.x
drone.y
drone.battery_remaining_m
drone.queue
drone.onboard_tasks
drone.status
```

协调器调用时直接收到这些对象：

```python
assignments = self.coordinator.assign(available, self.drones, self.now_minute)
```

本地派单把任务对象加入无人机队列；`DroneAgent.step()` 更新位置、电量和任务属性。队列中的任务与全局列表中对应任务共享对象引用，因此变更可以直接从环境对象中读取，不需要通过网络或数据库再取一次。

源码：`simulation/delivery_sim.py:40`、`:81`、`:579`、`:624`、`:665`。

### 三、Ray 模式：actor 执行状态，主进程获取副本

```mermaid
sequenceDiagram
    participant Main as 主进程 RaySimulationEnv
    participant Actor as 各无人机 actor
    participant KG as 知识存储
    Main->>Actor: snapshot.remote()
    Actor-->>Main: 位置、电量、队列、载货等快照
    Note over Main: ray.get 等待，构建 DroneStateProxy，中央调度
    Main->>Actor: assign.remote(task_payload)
    Actor-->>Main: accepted、任务状态、无人机快照
    Main->>Actor: step.remote(minutes, next_time)
    Note over Actor: DroneAgent.step 更新执行状态
    Actor-->>Main: drone、completed_tasks、events
    Note over Main: 合并全局任务与 Agent 状态
    Main->>KG: 写事件、Step 和可选 AgentState
```

#### 3.1 无人机本体在哪里

`_DroneActor.__init__()` 用序列化载荷重建 `DroneAgent`，保存在 `self.drone`。队列、在手任务、电量、位置等执行状态由这个对象维护。

主进程只保存 actor handle，即 `self.actors[drone_id]`，通过 Ray 调用该 actor 的方法。

#### 3.2 主进程怎样取最新快照

实际代码位于 `_sync_drones()`：

```python
snapshots = self.ray.get([
    actor.snapshot.remote()
    for actor in self.actors.values()
])
self.drones = [
    proxy_from_snapshot(snapshot, self.planner)
    for snapshot in snapshots
]
```

`snapshot()` 把 actor 内对象转换成可传输的数据；`ray.get()` 等待远程结果，`proxy_from_snapshot()` 在主进程创建 `DroneStateProxy`。代理中有位置、剩余电量、队列任务、载货任务、状态、容量和累计里程等字段，调度器据此计算成本与候选。

`release_and_assign()` 在派单前调用 `_sync_drones()`；在初步决策后及提交分配后也有同步。初步决策可能暂时改变主进程代理，最终是否接单由 actor 的返回值确认。

#### 3.3 动作执行后的更新如何回来

主进程并行提交所有 actor 的 `step.remote()`，然后等待结果。每个结果包含：

```text
drone             本步执行后的无人机快照
completed_tasks   本步完成任务的序列化状态
events            取货、充电、交接等事件载荷
```

主进程用这些结果重建 `self.drones`，并通过 `_apply_assigned_task()`、`_apply_picked_task()`、`_apply_completed_task()` 等方法，按任务 ID 更新全局 `self.tasks`。

因此主进程与 actor 不是共享一组可变 Python 对象。主进程保存决策和全局追踪所需副本，actor 保存实际推进执行所需对象，由显式消息同步。在每轮等待结束的步边界上汇总状态，也不能把该快照解释为随时自动刷新的共享内存。

源码：`simulation/ray_delivery_sim.py:191`、`:251`、`:309`、`:376`、`:456`、`:468`、`:519`、`:709`。

### 四、Neo4j、检查点与页面各保存什么

Neo4j 是运行状态的数据库记录层：

- `Drone`、`Task`：实体属性随对应写入更新。
- `Event`：派单、取货、完成、返航和互助等过程记录。
- `Step`：一次仿真步的全局汇总。
- `AgentState`：开启 `KG_RECORD_AGENT_STATE=1` 后，每步每个 Agent 的历史快照。
- `Run/run_id`：区分不同实验。

数据库属性的新鲜度取决于写入时机。例如未开启 AgentState 时，普通 Step 写入不会同时逐个刷新所有 Drone 位置；业务事件会更新对应实体。图中实体也不必包含尚未触发任何写入的全部原始任务。因此主进程的运行对象与数据库记录不能假定为任意时刻完全相同。

区域 LLM 可以另外查询 Neo4j 历史表现和事件，但构建候选所用的当前任务与 Agent 仍由上述内存状态提供。

检查点用于进程中断后的恢复：headless 将任务可变字段、Agent 状态、仿真时间和配置保存到 JSON，并校验完整性；恢复时先重建静态场景，再应用检查点、重建 actor，同时核对数据库 Step。普通运行不会每轮从检查点读取状态。

页面帧则是展示副本：后端把状态转换为 frame，通过 SSE 发送给浏览器。浏览器回看或暂停显示时，后端仍可继续推进；浏览器缓存不反向成为中央调度的数据源。离线 trace 保存一系列帧用于回放，也不等同于完整恢复状态。

源码：`simulation/knowledge.py:498`，`scripts/run_headless_sim.py:73`、`:284`，`simulation/checkpoint.py:93`。
