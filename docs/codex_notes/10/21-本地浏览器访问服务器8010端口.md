### 任务背景

用户在自己的电脑浏览器中访问 `http://localhost:8010/dynamic.html`，无法打开部署在服务器上的仿真页面，需要定位原因并给出不影响运行服务的访问方式。

### 关键结论

- 服务器 8010 端口正在监听，监听地址为 `127.0.0.1:8010`，不是所有网卡地址。
- 在服务器本机请求 `/dynamic.html` 返回 HTTP 200，说明检查时页面服务可用，不是服务没有启动。
- 本地电脑浏览器中的 localhost 指向本地电脑，不会自动指向远程服务器；需要通过 SSH 端口转发等方式把本地端口连接到远程端口。
- 由于服务仅绑定服务器回环地址，直接把 localhost 替换成服务器 IP 也不能直接访问该监听端口。
- 推荐 SSH 端口转发，无需修改监听地址、开放公网端口或重启服务。本次没有修改服务、创建隧道或中断仿真。

### 执行过的操作

- 阅读 `scripts/run_dynamic_sim.py` 中的监听配置：默认 `--host 127.0.0.1`、`--port 8010`。
- 运行 `ss -ltn '( sport = :8010 )'`：确认实际监听为 `127.0.0.1:8010`。
- 使用 curl 只请求服务器本机的 `http://127.0.0.1:8010/dynamic.html`：得到 HTTP 200；没有访问会触发仿真的 `/events`。
- 首次沙箱内网络检查因权限失败，随后经授权在沙箱外完成只读检查；没有把沙箱内的连接失败判断成服务故障。

### 后续建议

在用户自己的电脑终端执行，不是在远程服务器终端执行：

```bash
ssh -o ExitOnForwardFailure=yes -N -L 127.0.0.1:8010:127.0.0.1:8010 用户名@服务器IP
```

替换为实际 SSH 用户名和服务器地址；若 SSH 不是默认 22 端口，再增加 `-p 实际SSH端口`。认证成功后保持该终端窗口运行，浏览器打开：

```text
http://127.0.0.1:8010/dynamic.html
```

如果本地 8010 已被其他程序占用，可改用本地 18010，而远程端口仍保持 8010：

```bash
ssh -o ExitOnForwardFailure=yes -N -L 127.0.0.1:18010:127.0.0.1:8010 用户名@服务器IP
```

浏览器相应访问 `http://127.0.0.1:18010/dynamic.html`。如果使用 VS Code Remote SSH，也可在远程窗口的“端口”面板转发 8010，并打开面板显示的本地地址。

注意：原动态页面加载后会自动建立 `/events` 连接，可能启动或替换当前页面控制的仿真。因此在已有重要仿真运行期间，不要为了验证端口而反复打开、刷新页面；HTTP 静态页面检查本身未触发该行为。
