# 仿真写入期间动态添加索引能力核查

### 任务背景

用户希望确认：当前仿真持续向 Neo4j 写入数据时，能否动态增加索引，以及现有代码对此支持到什么程度。默认将“动态添加”理解为不重新导入数据、不重启仿真或数据库，在现有图谱上创建普通 RANGE 索引，并使后续写入自动进入索引。本次只读核查，没有实际创建索引或重启服务。

### 关键结论

- **数据库层支持在线增加普通索引。** 已有数据由 Neo4j 构建索引，后续相关数据变化由数据库自动维护；写入代码不需要手动更新索引或重新导入历史数据。
- **应用目前只有启动阶段的自动建索引。** 创建 Neo4jKnowledgeStore 时，根据配置检查固定的三组 AgentState 索引，缺失则创建，并同步等待 ONLINE 后才继续初始化。
- **仿真运行期间没有动态索引管理器。** 未发现配置热加载、周期巡检、根据慢查询自动选索引、HTTP 管理接口或后台索引创建任务。
- **运行中由独立管理连接新增 Event 等索引，无需改变现有写入语句。** 但不会自动由当前启动检查覆盖，也不保证查询一定采用新索引，应等 ONLINE 后检查计划。
- **自动维护现有索引不等于自动决定新增索引。** KG_AUTO_CREATE_INDEXES=0 只关闭应用的启动检查，不会关闭 Neo4j 对已有索引的维护，也不会删除任何索引。
- **在线不等于零影响。** 构建和维护索引会消耗磁盘、CPU、内存/I/O，并可能发生短暂 schema 锁等待；不应承诺持续写入完全无抖动。
- **19 项知识存储单元测试通过。** 测试使用 FakeIndexDriver，终端打印的“index created”是模拟调用，不是向真实数据库建索引。本次没有在写入源库现场执行边写边建实验。
- 若要实现“程序运行时根据需要自动新增索引”，仍需单独扩展应用管理逻辑；如果只是人工在线新增索引，现有标准 Cypher 写入方式已经兼容。

### 一、支持范围对照

| 能力 | 当前情况 | 实现主体 |
| --- | --- | --- |
| 启动时补齐固定的三组 AgentState 索引 | 已实现，受配置控制 | knowledge.py |
| 对已有数据后台构建索引 | 数据库支持 | Neo4j |
| 已有索引随新增/更新数据自动维护 | 支持，不需应用干预 | Neo4j |
| 仿真运行中通过其他管理连接增加普通索引 | 数据库支持，应用写入不需改写 | 人工/独立管理程序发起 |
| 根据查询耗时自动增加 Event/Task 等索引 | 未实现 | 需要应用扩展 |
| 修改配置后被正在运行的仿真自动热加载 | 未实现 | 无配置监听逻辑 |
| 运行中持续检查并补回被删除的索引 | 未实现 | 无后台巡检 |

Neo4j 官方说明，索引创建后由 DBMS 自动填充和更新；新索引在 POPULATING 阶段不能用于查询，要等 ONLINE。在线能力不表示每个原有查询计划都保证选择该索引。[索引自动维护](https://neo4j.com/docs/cypher-manual/current/indexes/)、[创建与状态](https://neo4j.com/docs/cypher-manual/current/indexes/performance-indexes/create-indexes/)

### 二、现有启动流程

代码路径：

```text
run_dynamic_sim.build_runtime
  → build_knowledge_store_from_env()
  → Neo4jKnowledgeStore.__init__()
  → 若 auto_create_indexes=True
      → ensure_agent_state_indexes()
      → SHOW INDEXES，检查现有定义
      → 对缺失项执行 CREATE INDEX ... IF NOT EXISTS
      → 轮询 SHOW INDEXES，等待 ONLINE
  → 创建/返回仿真环境
  → 仿真 step 与事件写入
```

`scripts/run_dynamic_sim.py:172` 构建知识存储，然后才创建本地或 Ray 仿真环境。headless 入口也会设置 KG_BACKEND、KG_RUN_ID、KG_RECORD_AGENT_STATE 等配置，复用相应环境构建流程。

关键代码：

- `simulation/knowledge.py:269`：构造时触发 ensure_agent_state_indexes。
- `simulation/knowledge.py:282`：检查、创建、同步等待索引的方法。
- `simulation/knowledge.py:887`：读取环境变量并构造知识存储。

#### 自动管理的固定索引

```text
AgentState(run_id, drone_id, step_index)
AgentState(run_id, region_id, step_index)
AgentState(run_id, step_index)
```

定义位于 AGENT_STATE_INDEXES。当前方法专用于 AgentState，不会因为增加了 56 条查询就自动推导并新增 Event/Drone/Task/Step 索引。

#### 当前已有的安全检查

- 按 RANGE 类型、NODE 实体、AgentState 标签和属性顺序识别等价索引，名称不同也可以复用。
- 同名但定义不同会报错，不直接覆盖现有索引。
- 等价索引处于 FAILED 时会报错，并保留 failureMessage 供排查。
- 对 POPULATING 状态轮询等待，不把刚执行 CREATE INDEX 当成已经可用。
- 等待超时抛出异常；不会静默忽略索引状态并假装已准备完成。

#### 配置边界

| 配置/参数 | 行为 |
| --- | --- |
| KG_BACKEND=neo4j 或 graph | 使用 Neo4j 存储；其他值使用内存存储 |
| KG_RECORD_AGENT_STATE=1 | 环境工厂开启状态快照，并成为默认自动建索引的前提 |
| KG_AUTO_CREATE_INDEXES | 环境工厂默认 1；设为 0 关闭启动索引检查 |
| KG_INDEX_WAIT_TIMEOUT_SECONDS | 默认 600 秒轮询等待预算 |
| index_poll_interval_seconds | 类参数默认 1 秒 |
| 直接实例化类的 auto_create_indexes | 默认 False，不等同环境工厂的默认行为 |

开关在构造对象时读取/确定，不是每个 step 重读。外部 shell 改 export 或修改源码中的索引列表，不会让已有 Python 对象自动更新。

等待预算也不是所有网络/DDL 操作的严格总耗时上限：当前 CREATE/SHOW 没有独立 Query timeout，如果一次请求本身长期等待，函数返回可能超过配置预算。索引已经提交创建后，即使客户端等待超时，也不能据此推断数据库自动撤销了该索引。

### 三、为什么当前写入方式兼容新增索引

当前写入使用标准 Driver 会话和 Cypher 事务：

- `record_step()`：MERGE Step/Drone/AgentState，并通过 SET 写入状态。
- `_write_event()`：MERGE Event/Task/Drone/Region，并设置业务属性。
- 任务关系和状态更新通过后续 Cypher 语句提交。

没有绕过 Neo4j 事务直接写数据库文件的逻辑。因此在相同数据库上新增普通索引后，对既有数据的填充，以及之后节点新增、属性更新的索引维护，都交由 Neo4j 处理，应用无需同时维护另一份索引内容。

此处主要讨论普通 RANGE 索引，不将其等同于新增唯一性约束、离线 neo4j-admin 导入或其他类型的特殊索引。普通索引会覆盖其标签/属性定义对应的数据，并不是仅为某一个 run 单独创建；run_id 只是索引键的一部分。

索引与 store 的一致性由数据库事务机制维护；普通同步索引与可配置的最终一致全文索引不是一回事。[Neo4j 索引一致性说明](https://neo4j.com/docs/operations-manual/current/performance/index-configuration/)

### 四、运行中新增的正确理解

如果运行时从独立管理连接提交索引创建，通常可按以下状态理解：

```text
仿真继续提交写入事务
          │
管理连接提交 CREATE INDEX
          ↓
POPULATING：Neo4j 填充已有数据并处理构建期间的数据变化
          ↓
ONLINE：新查询可以由规划器考虑使用，后续写入继续维护
```

“可以继续写”不等于没有等待或性能影响。创建 schema 对象和并发事务有锁与资源协调，数据量较大时构建可能明显占用 I/O、内存和 CPU。[并发访问与 schema 锁](https://neo4j.com/docs/operations-manual/current/database-internals/concurrent-data-access/)

当前 ensure_agent_state_indexes 是同步函数。如果以后直接在仿真主循环中调用它，主循环会等待该函数返回，不能把它当成已存在的后台异步功能。若需要自动动态管理，应使用独立管理连接/任务和明确的状态监控，不在每个 step 内执行建索引。

### 五、实例和操作边界

- 索引只对创建它的数据库生效。在克隆查询实例 61687 增加索引，不会自动出现在写入源实例 17687 或基线实例 57687。
- 仿真存储目前使用 driver.session() 的默认数据库，环境工厂没有读取 NEO4J_DATABASE 来指定写入数据库；人工管理时要确认与实际写入目标一致。不能只确认端口就忽略数据库名。
- 如果程序运行的是 memory backend，没有对应 Neo4j 持续写入，不能仅凭设置索引开关认为数据会自动入库。
- 不应为证明动态能力而临时修改原 A/B 实验的索引集合。本轮没有执行任何建/删索引操作。
- 没有 CREATE INDEX 权限的管理账号不能执行 schema 创建；数据库支持该能力不等于每个连接账号都具有权限。
