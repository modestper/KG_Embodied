# Neo4j 查询分阶段计时汇报表

### 任务背景

用户需要将 `/data/zc/datasets/LaDe/viewer/test_stage` 的分阶段计时数据整理为可直接放入组会汇报的表格，重点区分 Neo4j 服务端查询处理时间与连接池、TCP/Bolt、Driver 和调度等非服务端组合时间。

### 关键结论

- 无索引组的客户端平均总时间为 `1252.119 ms`，其中 Neo4j 服务端处理约 `1244.413 ms`，占 `99.38%`；瓶颈是数据库扫描与执行。
- 带索引组的客户端平均总时间降至 `123.144 ms`，但 Neo4j 服务端仅占 `11.914 ms`，约 `9.67%`；约 `90.33%` 已转移到连接/Bolt/Driver/调度等组合开销。
- 现有 Driver 公开指标无法继续精确拆分连接池等待、TCP 建连、Bolt 往返和 Driver 调度，因此汇报中必须称为“非服务端组合估算”，不能称为单独的 TCP 时间。
- i2 因 Cypher `BETWEEN` 语法错误在两组中全部失败，不列入成功查询延迟表。

## 指标定义

| 汇报名称 | 脚本字段 | 含义 |
|---|---|---|
| Neo4j 服务端查询处理 | `server_query_ms` | Bolt `t_first + t_last`；包含服务端解析、计划、索引/扫描、聚合和结果生成等 wall time，不是纯 CPU 时间 |
| 非服务端组合估算 | `client_nonserver_estimate_ms` | `client_query_total_ms - server_query_ms`；包含连接池获取/等待、必要时 TCP/Bolt 建连认证、本机 TCP 和 Docker 转发、Bolt 往返、Driver 解码、Python/线程调度等组合残差 |
| 客户端查询总时间 | `client_query_total_ms` | 从 `session.run()` 前到结果完整拉取和转换完成的端到端时间 |

三者的关系为：

```text
客户端查询总时间
= Neo4j 服务端查询处理
+ 非服务端组合估算
```

## 表 1：总体平均时间（建议放主汇报）

| 实验组 | Neo4j 服务端查询 | 服务端占比 | 连接池/TCP/Bolt/Driver 等组合估算 | 非服务端占比 | 客户端查询总时间 |
|---|---:|---:|---:|---:|---:|
| 无索引 `lade` | 1244.413 ms | 99.38% | 7.706 ms | 0.62% | 1252.119 ms |
| 带索引 `lade-index` | 11.914 ms | 9.67% | 111.230 ms | 90.33% | 123.144 ms |

**可直接用于 PPT 的解读：**

> 无索引时，单查询平均 1252 ms 中约 1244 ms 消耗在 Neo4j 服务端，数据库扫描是绝对瓶颈。建立索引后，服务端平均降到约 12 ms，但连接、Bolt、Driver 和调度等组合开销为约 111 ms，系统瓶颈已从数据库转移到客户端通信和并发管线。
