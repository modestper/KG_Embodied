# 前端控制仿真暂停与继续

日期：2026-10-28

### 任务背景

用户希望在前端增加暂停和继续按钮，实际控制后端模拟的推进。此前“暂停画面”只停止前端播放，后端仍会运行。本次新增独立的“暂停仿真 / 继续仿真”，保留原有画面播放功能和上一轮的服务器轨迹保存功能。

用户补充询问实现是否困难。本次采用 Step 之间等待的方式，改动范围可控，无需修改无人机调度算法或中断正在计算的 Step，因此继续实现并完成隔离验证。

### 关键结论

- 实时页右上角新增“暂停仿真”，点击后可切换为“继续仿真”，真正控制后端是否开始下一个 Step。
- 正在运行的 Step 会正常完成。如果其中包含 LLM 请求，也会等待该请求及本步处理完成；页面显示“正在暂停”，到达边界后显示“已暂停”和后端 Step。
- 暂停后不再调用下一次 `step_once()`，不推进仿真时间；继续后沿用同一个环境及步数，不重新运行或跳过步骤。
- 暂停期间仍发送状态心跳，页面可以回看历史；停止画面播放本身仍不会暂停后端。真实耗时计时继续记录经过的墙钟时间。
- 控制请求携带本次运行标识，旧页面不能操作新运行。重新运行、运行结束或连接中断时会重置前端控制状态；替换旧运行会唤醒其等待线程。
- 暂停控制位于 Local/Ray 共用的运行循环外层，不改动其调度实现。暂停只停止新的模拟步骤，不强行中断已经发出的模型请求或后台写入。
- 43 项 Python 测试、5 个现有前端测试文件，以及 9 项暂停流程、10 项轨迹保存流程、12 项既有页面的浏览器检查通过。
- 未重启正在运行的模拟服务，也未访问其 `/events`。更新后的后端需要重启后加载，再在新运行中使用该功能。

| `tests/simulation_control_test.py` | 新增当前 Step 完成后暂停、继续后步数连续、旧运行隔离和接口校验测试 |

控制接口为 `POST /api/simulation/control`，JSON 请求包含 `run_id` 和 `action`（`pause` 或 `resume`）。运行标识来自 SSE `init.simulation.run_id`；响应及 `simulation_state` 事件提供 `state`、`step_index`、`revision`。状态版本用于避免迟到的 HTTP 响应覆盖较新的 SSE 状态。

请求复用已有同源和 JSON 校验。运行结束或标识不匹配时返回 409，非法操作返回 400。暂停期间每秒提供状态更新，用于保持连接并发现页面断开；不使用忙循环等待。
