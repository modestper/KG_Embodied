# 前端展示代码分析与美化方案

日期：2026-10-21

### 任务背景

用户希望先分析现有前端展示代码，明确视觉、布局、交互和代码冗余可以优化的地方，再决定如何美化。本轮只做代码阅读、现状核查与方案整理，不修改前端、后端、数据或实验配置。

默认以桌面端实时仿真页为主要改造对象，同时检查静态回放页和数据概览页。建议的视觉方向是浅色科研监控台：地图突出、指标清晰、状态容易识别、技术细节按需展开。

本方案基于源码和本地数据结构分析，没有进行浏览器截图或真实页面交互验证。布局溢出、首屏拥挤等结论来自 DOM 顺序、尺寸约束和渲染调用分析，实际效果仍需在实施时检查。

没有访问实时 `/events`：当前页面初始化会连接该接口，而服务端会创建并替换活动仿真环境，不能把连接页面简单视为无副作用的预览。

### 关键结论

- 最值得先改的是信息层级：实时页同时铺开大量参数、地图、图谱查询、任务表、Agent 表、事件和 LLM 原始输入输出，主要展示内容被拉散。
- 现有浅色主题和公共样式可以保留发展；优先统一字号、间距、按钮层级和状态表达，无需为了美化先更换框架。
- 确认存在功能入口重复和绘图逻辑重复：两个重新运行按钮调用同一函数，两个视图重置入口调用同一函数；动态与静态脚本至少有 7 类函数在忽略空白后完全一致。
- 拖动地图、滚轮缩放、修改边界样式都会触发完整页面渲染，连带重建表格和日志内容。这是明确的重复工作，可能放大大规模场景的交互开销，实际耗时尚未测量。
- 展示语义有改进空间：配送中任务与等待任务使用同色；城市筛选不影响小时分布；静态页标题与说明写死了吉林、5 架无人机和 120 个任务。
- 响应式只有 900px 一个断点，部分网格的固定最小列宽在更宽的窗口就已经放不下；小屏还会先看到完整参数栏和纵向指标列表。
- 建议分阶段实施：先整理页面和视觉，再抽公共模块、减少重复渲染；历史缓存和大文件回放属于后续性能专项，不能以精简为由随意裁掉现有能力。

#### 三、需要一起澄清的展示含义

1. **“暂停”暂停的是前端画面。** [togglePlayback](/data/zc/datasets/LaDe/viewer/src/dynamic_app.mjs:238) 只暂停跟随或回放，SSE 继续接收帧，后端继续运行。建议按钮明确写“暂停画面”，状态区同时表达当前查看时间和后台进度。
2. **播放速度只影响历史回放。** [restartPlaybackTimer](/data/zc/datasets/LaDe/viewer/src/dynamic_app.mjs:257) 在跟随实时时不启动回放计时器；实时推送节奏由后端推送间隔控制。两个设置应分组并明确命名，避免用户以为“快速”会加快仿真计算。
3. **首次出现互助会自动暂停画面。** [applyFramePayload](/data/zc/datasets/LaDe/viewer/src/dynamic_app.mjs:375) 包含这项逻辑，但当前状态提示没有解释暂停原因。建议显示“检测到互助，画面已暂停”的简短说明，保留现有演示能力。
4. **地图缺少配送中状态的独立表达。** [drawTasks](/data/zc/datasets/LaDe/viewer/src/dynamic_app.mjs:980) 只区分 `completed` 和 `assigned`，其他状态都画成绿色；服务端确实会发送 `picked_up`。本地调用现有函数确认 `waiting` 与 `picked_up` 都得到 `#1b8a6b`。建议统一地图、图例、任务表的状态映射，并区分未下发与已下发等待任务。
5. **城市筛选后的小时图仍是全局数据。** [buildFilteredSummary](/data/zc/datasets/LaDe/viewer/src/data.mjs:26) 筛选了城市和样本，但小时序列始终取 `dataset.hourly[taskType]`。读取实际 `summary.json` 并比较上海、吉林筛选结果，小时序列相同。首轮可标注“全局小时分布”；若需要城市联动，必须扩展汇总数据，不能从当前结构直接得到准确的逐城小时统计。
6. **静态页场景信息与文件可能不符。** [simulation.html](/data/zc/datasets/LaDe/viewer/simulation.html:44) 写死吉林、5 架无人机和 120 个任务，而当前索引首个 trace 是重庆 12 个任务、3 架无人机。应按所选 trace 的元数据生成标题与说明。静态页的“迟到任务”读取最终 `trace.metrics`，而“完成任务”读取当前帧，建议标明最终统计或统一到当前帧口径。

源码行数较多不等于全部冗余。实时页集中了数据接收、时间轴、表格和绘图，主要问题是职责边界和重复工作，不能按行数直接删代码。

以下内容也应保留：

- 图谱面板的 5 个耗时代表不同计时范围，有包含关系；可以把次要项折叠，不能合成一个数或相加。查询解释可收进帮助区，查询只在手动提交时执行的生命周期应保持独立。
- 仿真时间、真实执行耗时是两个不同指标；连接状态、后台运行状态、画面回放状态也不同，适合集中表达，不能混成一个模糊状态。
- 时间轴的元素级与 window 级拖动结束监听处理不同边界情况，不能当重复绑定随手删除；历史回看时地图、任务、Agent 和事件应继续对应同一帧。
- 互助角色、区域边界、回退数据格式和旧 trace 兼容分支有实际用途，抽公共模块时需要显式保留。

#### 五、推荐的页面组织方案

建议先做一个以地图为中心的浅色监控台，保留三个页面入口，用相同的导航、指标、面板和控件样式。

| 区域 | 默认展示内容 | 按需展开内容 |
| --- | --- | --- |
| 顶部 | 统一导航、城市与日期、当前连接状态 | 后端、调度器、模型等运行详情 |
| 左侧场景设置 | 城市、日期、无人机数、任务数、重新运行 | 最大步数、采样、推送间隔、Ray 和 LLM 参数 |
| 指标区 | 完成进度、无人机总数与空闲数、迟到数量 | 仿真时间和执行耗时以紧凑状态栏补充，保留完整含义 |
| 主地图 | 轨迹、区域、状态图例、集中地图工具 | 图层开关、边界样式、选中对象详情 |
| 地图时间控制 | 暂停画面、历史回放速度、时间轴、回到实时 | 当前帧与后台最新帧详情 |
| 数据区 | 默认任务与 Agent 状态，可用标签切换 | 互助筛选、任务详情、区域筛选 |
| 事件摘要 | 近期重要事件，突出互助和异常 | 原始事件字段与更多记录 |
| 专业工具 | “知识图谱查询”“LLM 调用”明确入口 | 编辑器、详细耗时、原始输入输出与历史 |

大屏时可让地图旁显示紧凑事件摘要；窗口变窄时依次下移，优先保证地图与表格的可读宽度。参数区在小屏默认收起，避免打开页面后先滚动大量配置。

视觉细化建议：

- 使用浅灰背景、白色面板和单一蓝色操作主色，减少无意义装饰；成功、进行中、风险、故障保留独立语义色。
- 统一标题、正文、辅助说明、指标数字的层级；数字列和计时使用等宽数字，长 ID 保留复制或完整查看入口。
- 状态使用“颜色 + 文本/形状”，避免只靠红绿区分。无人机身份色和任务状态色承担不同含义，需要在图例中分清。
- 当前 6 色无人机调色板会循环使用，100 架以上时不应依赖颜色唯一识别；增加选中高亮、ID 和区域筛选比无限扩充颜色更实用。
- 图例尽量放到 DOM 覆盖层或独立栏，便于自适应、交互和键盘操作；纯 Canvas 中的文字不会随着 CSS 主题自动更新。
- 增加“适配当前任务区域”和“查看全部 depot”的视图选项。当前地图范围包含该城市全部充电 depot，小任务样本有可能被压缩；默认取景需兼顾当前无人机和目标，不能简单裁掉远处状态。

#### 六、代码整理与规模相关优化

首轮可以继续使用现有 HTML、CSS 和 ES modules。已有 `.panel`、`.kpis`、`.timeline` 等公共规则应复用，先完善语义变量和样式分区，避免为每张卡片增加一套近似样式。

下一轮有明确收益的模块边界是：

- 公共 Canvas 尺寸处理、坐标投影、网格和基础图形。
- 公共拖拽、缩放、重置视口控制。
- 实时页的指标、任务表、Agent 表、事件与 LLM 呈现。
- 统一状态名称、语义色、时间和数值格式化。

SSE、实时跟随和历史回放仍由各自控制层管理；现有查询、时间轴、区域与互助模块继续保留。概览页使用经纬度，仿真页使用平面坐标，公共投影工具需要明确坐标类型，不能直接混用。

大规模数据另外考虑：

- 任务表目前一次渲染全部已下发任务，`max-height` 只限制可视高度，不减少 DOM 数量。先做筛选和分页，数据规模证明有必要后再引入虚拟列表。
- `FrameTimeline` 保存所有收到的帧，没有容量上限。以后可评估持久化或分块回放，但要先明确完整历史要求，不应为了内存直接删掉旧帧。
- 静态索引声明部分 trace 大小约 55、251、328 MiB，而当前使用一次性 `response.json()`。加载状态和文件大小提示可先做，数据分块需要单独设计文件格式和读取流程。
- Canvas 当前有 760×460 的最小内部尺寸；窄屏或较低设备像素比时，内部逻辑尺寸与显示尺寸可能不一致，需同步检查画面清晰度、文字大小和拖拽坐标。
- 目前未做性能基准，不能声称页面已经发生特定程度的卡顿或给出提升百分比。
