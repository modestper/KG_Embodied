# LaDe 技术方案分领域速览

### 任务背景

基于本次对当前工作区的代码分析，按技术领域汇总项目使用的方案，供另一个项目参考选型。本文描述现有实现，不新增技术选型或修改业务代码。

### 关键结论

- 主体组合是 Python 仿真核心、可选 Ray 并行执行、内存或 Neo4j 知识存储、可选 LLM 调度，以及原生浏览器可视化。
- Agent 的执行可并行，但派单、互助协调和知识写入主要集中在驱动进程。
- 图数据和时序状态统一放在 Neo4j 的实体、事件和快照中；向量检索与多模态统一管理尚未形成代码中的完整实现。
- 前端通过 SSE 接收统一帧，历史回看使用浏览器帧缓存，离线回放使用 JSON trace。
- 实时 LLM 使用区域上下文摘要；独立的 56 个决策上下文查询并未自动接入实时调度。

### 技术领域与对应方案

| 领域 | 当前技术方案 | 主要作用 / 实现方式 |
|---|---|---|
| 后端语言 | Python、标准库、dataclass | 定义任务、Agent、环境、状态推进和工具脚本 |
| 数据接入 | CSV、Python csv/json、固定种子采样 | 读取 LaDe 订单，清洗时间与坐标，生成任务 |
| 空间处理 | EPSG:3857、欧氏距离、固定 depot、区域边界预计算 | 把经纬度转为平面坐标，计算移动与展示区域 |
| 仿真引擎 | 自研离散时间步仿真 | 每步释放任务、派单、移动、产生事件并更新指标 |
| 多 Agent 执行 | 本地顺序执行 / Ray actor | 一架无人机对应一个 actor，驱动进程按步汇总结果 |
| 规则调度 | 同区域优先、贪心拍卖、加权成本函数 | 综合距离、队列、迟到、跨区和电量风险分配任务 |
| 协作互助 | 自研规则、预计路线与能量检查、任务重派和固定点交接 | 处理故障、低电量和时效风险 |
| LLM 接入 | vLLM 等兼容服务、HTTP JSON、urllib.request | 默认启动配置为 Qwen2.5-7B；区域批量决策、JSON 响应、异常时规则回退 |
| 知识存储 | 内存事件列表 / Neo4j 属性图 | 保存实体、派单、取货、完成、返航和互助关系 |
| 图访问与查询 | Neo4j Python Driver、Bolt、Cypher | 图写入、区域记忆读取、手动查询与实验查询 |
| 时序建模 | Run、Event、Step、AgentState、复合 RANGE 索引 | 运行隔离、事件历史、全局步摘要、Agent 历史状态 |
| HTTP 服务 | ThreadingHTTPServer、SimpleHTTPRequestHandler | 提供页面、静态文件、SSE 和图查询接口 |
| 实时通信 | SSE、浏览器 EventSource | 推送 init/frame/done，实时更新页面 |
| 前端与绘图 | 原生 HTML/CSS、JavaScript ES modules、Canvas 2D | 地图、轨迹、任务和 Agent 表格、KG/LLM 面板 |
| 回放 | JSON trace、trace 索引、FrameTimeline | 离线播放与浏览器当前连接的历史回看 |
| 长任务恢复 | JSON 检查点、SHA-256、fsync、原子替换、重试和 supervisor | 检测检查点损坏、保存完整状态、失败后续跑 |
| 查询性能实验 | ThreadPoolExecutor、模板目录、JSONL、分位数和阶段计时 | 56 个通用模板与 56 个上下文查询；统计延迟、吞吐、结果数与失败数 |
| 配置与启动 | Bash、环境变量、argparse、Conda lade 环境 | 选择执行、知识与模型后端，组织实验参数 |
| 测试 | Python unittest/mock/FakeRay、Node 内置测试运行器 | 验证状态、调度、图写入、恢复和前端纯逻辑 |

### 最值得迁移的组合

| 新项目需求 | 可参考的组合 |
|---|---|
| 快速验证业务 | Python 领域模型 + 本地步进 + 规则策略 + 内存事件 |
| 展示与回放 | 统一 Frame + SSE + Canvas + JSON trace |
| 共享知识与历史查询 | run 隔离 + Neo4j 实体/事件/快照 + Cypher 模板 |
| 模型增强决策 | 上下文筛选 + JSON 决策 + 合法性检查 + 规则回退 |
| 大规模、长时间实验 | Ray actor + headless + 原子检查点 + 压测记录 |

这些是复用方向。迁移时仍需重写目标项目的数据接入、任务含义、资源约束、成本函数和协作协议。
