### 关键结论

- 排查时 8010 端口没有服务监听，`run_dynamic_sim.py` 和 Ray 进程均已退出；浏览器保留的是无法接收 frame 的旧页面。
- 原 `s8010` 使用裸 `python3`，新终端中会解析到未安装 Ray 的 base Conda Python，行为依赖调用命令时是否已激活 `lade` 环境。
- 原启动命令没有限制 Ray CPU 数，Ray 会按整机资源预启动大量 worker；最新 Ray 会话确实创建了大量 worker，而 HTTP 服务必须等 Ray 初始化完成后才监听 8010。
- Neo4j `bolt://127.0.0.1:17687` 已通过只读 `RETURN 1` 验证，当前不是图数据库不可用导致的空白。
- 修复后在独立端口完成端到端验证：动态页面返回 HTTP 200，SSE 返回 `init` 和两个包含无人机坐标的 `frame`，前后端数据链路正常。
- 当前没有遗留的测试服务器或 Ray 进程。
- 用户再次启动后产生了 `11:16:13` Ray 会话，但约一分钟后主进程和 8010 服务再次退出；Ray 日志未记录业务异常、OOM 或 worker 启动失败，主进程 traceback 只存在于未重定向的启动终端中。
