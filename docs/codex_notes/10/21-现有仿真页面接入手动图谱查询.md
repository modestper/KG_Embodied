### 任务背景

在已有的实时 Drone 仿真页面中增加手动查询功能：用户自己填写查询指令，查看 Neo4j 返回结果，并分析时间开销；不使用固定 i/q 查询集自动压测，不新建另一套前端页面。

本次按“只读 Cypher + JSON 参数”实现，不包含自然语言转 Cypher 或调用 LLM。没有重启已有服务、打开真实仿真的 SSE 连接、修改实验结果或清理用户文件。

### 关键结论

- 已在 `dynamic.html` 的地图下方加入“知识图谱手动查询”面板，支持自定义 Cypher、JSON 参数、结果表格、数据库提示、最近 20 次成功查询耗时，以及结果与历史 JSON 导出。
- 查询只由执行按钮触发；页面初始化仅读取服务配置，不自动查询图谱，也不随仿真帧更新触发查询。查询使用独立驱动和连接池，不借用仿真写入连接。
- 分别显示数据库报告耗时、后端查询耗时、准备与只读校验耗时、后端处理总耗时、网页请求总耗时。各指标存在包含关系，不能直接相加或用相减值精确代替网络耗时。
- 通过保守语句检查、EXPLAIN 返回类型检查、READ 会话和不提交的显式事务降低误写风险；拒绝写入、管理指令及任意扩展过程调用。没有把 READ 路由模式当成数据库权限机制。
- 默认最多展示 100 行、允许调整到 200 行；结果行 JSON 数据预算为 1 MiB；事务默认 5 秒、最高 15 秒；全服务同时仅允许一个手动查询。展示截断不代表数据库扫描工作量被限制，仍需合理设置过滤条件和 Cypher LIMIT。
- 查询服务没有创建节点、属性、关系或索引；原有仿真写入模块的启动建索引逻辑保持不变。现有 i0–i55 查询能通过只读语句检查，但并未作为网页查询目录载入。

#### 连接配置

查询服务在页面服务器启动时读取环境配置；驱动到首次实际查询才建立，不会因读取面板配置而连接数据库。

| 查询配置 | 未设置时的回退 |
| --- | --- |
| `GRAPH_QUERY_URI` | `NEO4J_URI`；若 KG_BACKEND 为 neo4j/graph 且未设置地址，则使用原写入模块同样的 `bolt://127.0.0.1:7687` 默认地址 |
| `GRAPH_QUERY_USER` | `NEO4J_USER`，再回退 `neo4j` |
| `GRAPH_QUERY_PASSWORD` | `NEO4J_PASSWORD`，再回退空值；不硬编码口令 |
| `GRAPH_QUERY_DATABASE` | `NEO4J_DATABASE`；都未设置则使用数据库用户默认库 |

`KG_RUN_ID` 只作为环境提示显示，不会自动添加到用户查询参数中。应在查询和参数中显式指定所需 run_id。原写入模块使用默认库，因此自行设置查询库名时需确认它确实是预期的数据集。

如果原有服务已经带有正确的 `NEO4J_*` 配置，可沿用原启动命令，无须额外增加查询环境变量。如果需要查另一份测试库，可以在原服务启动环境中设置 `GRAPH_QUERY_*`，不会改变仿真写入地址。本版一次连接一个服务端配置目标，不支持浏览器自行填写任意数据库地址或口令。

#### 如何使用

1. 等待正在运行的仿真结束，或者明确确认可以中断后，再按原有方式重启页面服务。不要为了加载新代码擅自重置仿真。
2. 打开原来的 `dynamic.html`。注意：原页面会自动连接 `/events`，此行为原先就存在，本次没有修改。
3. 在地图下方确认查询目标，填写 Cypher 和 JSON 参数，点击“执行只读查询”。
4. 查看结果、提示和五项耗时；需要分析或比较时，点击“导出结果与耗时 JSON”。历史仅保存在当前页面内存中，刷新会清空；导出含当前结果、原始查询参数及最近 20 次成功查询的指标，不包含前 19 次查询的完整结果行。

默认示例只查询现有 Run 节点：

```cypher
MATCH (r:Run)
RETURN r.id AS run_id
LIMIT $limit
```

参数为 `{"limit": 20}`。

接近 drone 在请求 LLM 前读取自身状态的手动示例，使用已有 AgentState 结构：

```cypher
MATCH (a:AgentState {run_id: $run_id, drone_id: $drone_id})
WHERE a.step_index <= $step_index
RETURN a.step_index AS resolved_step,
       a.time_minute AS time_minute,
       a.status AS status,
       a.battery_remaining_m AS battery_remaining_m,
       a.queue_len AS queue_len
ORDER BY a.step_index DESC
LIMIT 1
```

对应参数示例：

```json
{"run_id":"hangzhou-0621-headless-002","drone_id":"drone-1","step_index":2300}
```

查询结果是否存在取决于所连接数据集及其快照记录情况；只有开启过 AgentState 写入且保存了相应时刻的数据，才能返回相应快照。此示例不假设互助/故障属性或不存在的关系。

#### 五种时间的边界

| 页面指标 | 返回字段 | 统计范围 |
| --- | --- | --- |
| 数据库报告耗时 | `server_reported_ms` | Neo4j 的 `result_available_after + result_consumed_after`；同时保留两个原始字段。不是 CPU 时间，服务器通常以毫秒粒度报告，0 不等于没有执行 |
| 后端查询耗时 | `query_client_ms` | 实际 Cypher 的 `tx.run`、取回并转换被展示的记录、计算结果行字节预算，以及 consume 获取摘要；不含之前的 EXPLAIN 和之后的回滚 |
| 准备与只读校验 | `validation_ms` | 进入查询服务到 EXPLAIN 完成，包括输入校验、首次驱动准备、连接/事务建立及只读类型复核 |
| 后端处理总耗时 | `backend_total_ms` | 进入查询服务到准备返回结果，含准备、查询、回滚、会话清理和通知转换；不含接口外的请求 JSON 解析和最终 HTTP 响应 JSON 序列化 |
| 网页请求总耗时 | `browser_request_ms` | 浏览器发请求前到接收并解析 JSON 完成，包含请求准备、HTTP、后端处理、响应序列化、传输及浏览器 JSON 解析；不包含随后构建结果表格和浏览器绘制 |

服务器侧使用 `time.perf_counter()`，网页侧使用 `performance.now()`。不跨机器相减绝对时间戳；浏览器调度和计时精度也会影响观测值。数据库摘要的含义参考 [Neo4j 结果摘要文档](https://neo4j.com/docs/python-manual/current/result-summary/)，网页单调时钟参考 [MDN performance.now](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now)。

EXPLAIN 不执行业务查询，但可能生成/预热执行计划缓存，因此这里的“后端查询耗时”不能当作未经预热的首次编译耗时。结果截断后会 consume/discard 剩余记录来拿到摘要，不保证数据库停止扫描；用大 collect 或缺少过滤的聚合仍可能耗费较多资源。

#### 与之前 A/B 数据集压测的关系

网页多出 HTTP、响应 JSON、浏览器解析及渲染开销；本实现还多一次 EXPLAIN 校验。与此同时，网页当前限制为单个手动查询，而之前的测试是 100 workers，竞争程度不同。因此不能笼统保证“更慢”或“更快”，也不能将网页总耗时与之前的数据库客户端耗时直接相除。

如果要比较索引与无索引，需固定同一 Cypher、参数、数据版本、返回上限、计时边界、并发量、缓存预热状态及其他负载。实时仿真同时写入会争用 CPU、内存、磁盘和缓存；查询使用独立驱动不代表资源隔离。拖动/暂停页面时间轴只是回看，不会冻结数据库状态。
