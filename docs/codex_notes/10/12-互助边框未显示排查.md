### 任务背景

用户使用 `Chongqing / 0615 / 10 tasks / 3 drones` 运行动态仿真，但没有在页面上看到求助无人机的红色外框和援助无人机的绿色外框。本次任务需要确认互助是否实际触发，并修复前端展示容易错过的问题。

### 关键结论

- 互助逻辑实际已经触发：Neo4j 的 `help-1012` 数据中存在 `drone-1` 因低电请求帮助、`drone-3` 接管任务 `1100131` 的事件。
- 原来的互助有效画面只持续约 55 帧，在当前播放速度下约 5 秒，很容易直接播放过去。
- 运行中的 8010 服务存在多个浏览器 SSE 连接；服务端只允许一个活动仿真环境，旧标签页自动重连时可能反过来替换新标签页的运行实例。
- 前端现在会在第一次出现有效互助状态时自动暂停，保留红绿边框画面，用户点击“播放”后才继续。
- 红色/绿色外框由 7px 且覆盖 2px 白边改成无白边覆盖的 9px 粗边，地图缩放较小时也更明显。
- 服务端现在会向被新连接替换的旧 SSE 流发送 `superseded` 事件；旧页面收到后停止播放和自动重连，避免多个页面相互抢占。
- 当前 8010 进程未被停止。前端静态代码硬刷新后可更新，但服务端 SSE 修复必须重启 `s8010` 后生效。
- Neo4j 中同一 `KG_RUN_ID=help-1012` 出现多个 Run 节点及其他城市数据，说明多次实验复用了同一个 run id；后续正式实验应使用唯一 run id，避免图谱数据混合。
