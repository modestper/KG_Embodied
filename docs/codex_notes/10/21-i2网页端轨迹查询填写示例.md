### 任务背景

用户希望将已有 i2（recent_self_trajectory）用于现有网页的手动查询面板，需要可直接粘贴的 Cypher 和 JSON 参数。

### 关键结论

- 不需要改动 i2 的查询逻辑；仅粘贴 `cypher` 字符串内的正文，不粘贴 Python 的 ContextQuery 定义。
- 查询基于现有 AgentState 节点及其实际字段，不引入新节点、关系、属性或索引。
- 在 JSON 参数框中提供 run_id、drone_id、start_step、step_index 和 limit 五个参数；网页不会像压测脚本那样自动计算 start_step。
- 示例读取 drone-1 在第 2281–2300 步范围内最多 20 条轨迹状态记录，最新记录排在前面；缺失快照不会自动补齐。
- step_index=2300 是固定的历史查询上界，不会因网页实时刷新而自动变化；若要查当前最新轨迹，需要更新参数或另外设计自动解析最新步的版本。
- 本次仅核对代码并提供填写说明，没有运行数据库查询、改动查询代码、创建索引或重启服务。

### 执行过的操作

- 阅读 `scripts/lade_llm_context_queries.py` 中 i2 定义，确认五个必需参数和返回字段。
- 阅读同文件的 build_params：脚本按 `max(0, step_index - history_steps + 1)` 计算 start_step；网页手动面板没有这层自动参数构造。
- 阅读 `dynamic.html` 中 Cypher、JSON 参数和最多展示行数的输入控件。

### 修改内容

仅新增本说明文件，未修改业务代码。

在网页“只读 Cypher”框粘贴：

```cypher
MATCH (a:AgentState {run_id: $run_id, drone_id: $drone_id})
WHERE a.step_index >= $start_step AND a.step_index <= $step_index
RETURN a.step_index AS step_index,
       a.time_minute AS time_minute,
       a.x AS x,
       a.y AS y,
       a.status AS status,
       a.queue_len AS queue_len,
       a.onboard_count AS onboard_count,
       a.battery_remaining_m AS battery_remaining_m
ORDER BY a.step_index DESC
LIMIT $limit
```

在“JSON 参数”框粘贴：

```json
{
  "run_id": "hangzhou-0621-headless-002",
  "drone_id": "drone-1",
  "start_step": 2281,
  "step_index": 2300,
  "limit": 20
}
```

将“最多展示行数”保持为默认 100 即可，也可以设为 20 或更大（面板最高 200）；这是网页展示上限，不是 Cypher 中的 limit 参数，两者相互独立。

参数含义：

| 参数 | 含义 |
| --- | --- |
| run_id | 仿真运行标识，必须与查询目标库中的实际数据一致 |
| drone_id | 指定无人机，而不是本轮所有无人机 |
| start_step | 时间窗起始仿真步，包含边界 |
| step_index | 时间窗结束仿真步，包含边界 |
| limit | 按步编号降序排列后最多返回多少条记录 |

如果要设置最近 N 个步编号的窗口，可手动计算 `start_step = max(0, step_index - N + 1)`。例如结束步为 2300、窗口为 20 步，则起始步为 2281。start_step/step_index 是步编号，不是分钟；真实仿真时间由返回的 time_minute 表示。

### 后续建议

- 先确认面板显示的数据库地址和数据库名，再执行示例。样例参数来自此前使用过的 run_id 和 step_index，不表示当前数据库最新步就是 2300。
- 若没有返回行，先核对运行标识、无人机标识和时间窗是否正确，再确认该数据集是否实际记录了 AgentState；不要仅凭返回 0 行判定查询失败或没有索引。
- 如需给 LLM 提供按时间向前展开的轨迹，当前结果可在消费端逆序排列。不要直接把原查询 ORDER BY 改为 ASC 后仍保留较小 limit，否则取得的可能是窗口内最早记录，而非最近记录。
- 如需与原脚本对照，保持相同 run_id、drone_id、起止步、limit 和数据版本；网页的网页请求总耗时与脚本客户端查询耗时边界不同，不能直接等同。
