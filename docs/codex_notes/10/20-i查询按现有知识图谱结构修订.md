# i 系列查询按现有知识图谱结构修订

### 任务背景

用户明确要求：新增查询必须以目前实际知识图谱的节点、关系和属性为基础，不得把代码未来支持的结构当成已经入库的业务数据。本次以 `bolt://127.0.0.1:57687`、数据库 `neo4j`、run `hangzhou-0621-headless-002` 为对齐依据，修订此前扩充的 i 系列。q 系列不属于本次修改范围。

### 关键结论

- 保留连续编号 `i0-i55`，仍为 56 条，但部分编号的查询名称和业务含义已修订，不应与此前版本直接混合比较。
- 实查库中有 7 类节点、12 类关系；查询仅使用这些结构及实际存在的属性、事件类型，不增加图谱节点、关系、属性或索引。
- 删除内置查询对协作关系、协作角色和故障扩展字段的依赖，包括 `ASSISTS/TAKES_OVER`、`source_drone_id/helper_drone_id`、`failure_mode/takeover_mode`、交接字段等；没有靠关闭通知来掩盖差异。
- 不匹配的协作历史查询已改成真实派单、取件、在途、完成、区域服务及等待耗时查询。附近无人机只作为决策候选，不被描述成“已经协助的伙伴”。
- 新增保守的实际图谱结构约束、内置目录启动检查和回归测试，防止后续扩充再次无意加入约束外的标签、关系、属性或事件类型。自定义 query-file 不属于该内置约束。
- 新目录版本为 `i56-observed-graph-v2`，写入 context、逐条查询日志、summary 和 dry-run，供区分新旧实验。
- 31 项本地回归通过；5 项真实库只读集成测试通过，覆盖 56 条 EXPLAIN、34 条顺序执行检查及事件时间语义核对；没有创建测试业务节点或启动完整并发压测。
- 合法空结果仍然可能存在。当前 Task/Drone 属性也不会因为传入旧 step 自动成为历史快照；结构匹配、非空覆盖、历史一致性和性能达标需要分别验证。

### 一、实际图谱依据

#### 真实节点

| 标签 | 已核实的基础字段/用途 |
| --- | --- |
| Run | id；标识一次实验 |
| Region | id、run_id、city、depot_x/depot_y；区域和已知 depot |
| Drone | 身份、坐标、status、队列/载货、速度、电量配置及累计距离等 |
| Task | 身份、区域、释放/deadline、取送坐标、分配/取件/完成状态等 |
| Event | 身份、actor、type、时间、区域及按类型附加的队列/载货/电量/late 等 |
| Step | step、时间、完成/未完成任务、各状态 drone 数量及累计距离 |
| AgentState | drone_id、step、时间、坐标、status、queue_len、onboard_count、电量及累计距离 |

字段完整约束直接保存在 `scripts/lade_llm_context_templates.py` 的 `GRAPH_NODE_PROPERTIES` 中。核查结合小体量实体实际属性集合和 AgentState 有限样本，不把全库 property token 登记当成该 run 上存在非空业务值的证明。

#### 真实关系

```text
IN_RUN       IN_STEP       OF_DRONE
HOME_REGION  CURRENTLY_IN  BELONGS_TO
ABOUT_DRONE  ABOUT_TASK    IN_REGION
ASSIGNED     CARRYING      COMPLETED
```

当前库没有 `ASSISTS/HANDOVER_TO/TAKES_OVER/ABOUT_SOURCE_DRONE/ABOUT_HELPER_DRONE` 等关系。之前扩充使用的是更新后的写入代码能力，不是这批库的实际业务结构，这是本次纠正的根本原因。

实际 ASSIGNED 关系观察到 time/time_minute；CARRYING 有 active、pickup_time/pickup_time_minute 和部分完成时间；COMPLETED 有 time/time_minute/late。查询匹配 ASSIGNED|CARRYING 时，对缺失的 active 仍使用 coalesce，并结合 Task 当前状态和承担者判断，不把历史边全部当成有效任务。

#### 实际事件

```text
task_assigned
task_picked_up
task_completed
drone_low_battery
drone_returning_to_charge
drone_charged
```

不再在内置目录中假定存在求助、派遣、接管或交接事件。计算输出列（例如 distance_m、pickup_wait_minutes、candidate_drone_id）只是已有字段计算所得或返回别名，不是新造的图谱属性。

### 四、查询包和测试命令

原命令的 `--queries all` 仍能使用，100 个 drone × 20 次重复仍是 2000 个 context、112000 次模板查询；但是查询内容已改变，不能复用旧日志作不加区分的统计。

| 查询包 | 条数 | 用途 |
| --- | ---: | --- |
| core | 7 | 基础上下文 |
| decision | 9 | 决策前基础信息 |
| coordination | 5 | 区域/伙伴态势 |
| diagnostic | 7 | 状态诊断 |
| task_decision | 9 | 当前任务动作与风险 |
| energy_safety | 8 | 电量和已知返航信息 |
| request_help | 10 | 判断是否需要求助的依据，不读取不存在的求助事件 |
| provide_help | 8 | 判断自身资源与附近任务，不声称已经承担协助 |
| task_progress | 10 | 派单、取件、在途和完成反馈 |
| recovery | 9 | 状态、停滞、电量和数据就绪信息 |
| memory_review | 9 | 短期状态与真实业务历史 |
| local_awareness | 9 | 附近伙伴和区域资源/流量 |
| data_readiness | 6 | 状态与配置可用性 |

旧 `handover` 包已移除，由 `task_progress` 替代；当前数据不支持把它叫作实物交接查询。原 `request_help/provide_help` 名字保留，仅表示 LLM 决策阶段，内容都是已有数据的判断依据。

先用一个 drone、repeat 1 做功能检查；正式压测使用独立的新输出目录。两个 JSONL 追加写入、summary 覆盖写入的行为未变。没有改端口、数据库默认值或驱动通知配置；没有为测试创建索引。

### 五、验证结果与边界

- 本地回归：31 项通过；常规命令另有 5 项真实库测试按设计跳过。
- 只读集成：5 项全部通过；逐条验证 56 条 EXPLAIN，没有 01N50/01N51/01N52 未知结构通知。
- 34 条当前态/事件查询在真实库顺序执行，无未知结构通知。它们不是 34 条全部保证非空：当前任务和某些窗口允许合法空结果。
- 独立核对 i50 的派单/取件关联与时间边界，以及 i51、i54 的两种真实耗时间隔。
- 初次验证按 30 分钟窗口检查时，drone-1 的部分派单/充电事件为空；测试随后明确使用更宽历史窗口取得真实已有记录，不造数据，也不改变 CLI 默认 30 分钟。
- 其余涉及 AgentState 的查询完成结构约束与 EXPLAIN 检查。本次不在无属性索引的基线库反复启动全历史扫描，不将这部分说成已经完成全量实际执行或性能验证。
- 普通、single、stages 三入口离线 dry-run 各产生 56 条参数计划；Python 编译、普通/single 一致性检查通过。
- 第一轮只读集成命令受到沙箱 socket 权限限制，经授权连接本机数据库后完成验证；数据库未被写入。
- 测试不验证“所有业务场景都非空”，不证明 100 并发性能达标，也不解决 Task 历史版本缺失。

只读集成测试命令：

```bash
LADE_CONTEXT_INTEGRATION_URI=bolt://127.0.0.1:57687 \
LADE_CONTEXT_READ_ONLY=1 \
LADE_CONTEXT_RUN_ID=hangzhou-0621-headless-002 \
./run_in_lade.sh python -m unittest -v tests.lade_llm_context_queries_integration_test
```

可通过 LADE_CONTEXT_DRONE_ID、LADE_CONTEXT_STEP_INDEX、LADE_CONTEXT_EVENT_WINDOW_MINUTES 选择已存在的真实样本。没有配置这些只读 opt-in 条件时跳过，旧 ROLLBACK_FIXTURE 标记不再启用测试。
