# 模拟结束后手动保存轨迹方案

日期：2026-10-28

### 任务背景

用户希望直接从刚结束的模拟中生成轨迹，由用户主动点击保存，并选择保存文件夹。本轮评估实现难度、现有数据是否足够，以及保存和回放如何衔接，未修改功能代码。

默认理解：保存到浏览器所在电脑的本地文件夹。如果目标是模拟服务器上的任意目录，则需要另一套服务端保存接口，不属于以下本地另存为方案。

### 关键结论

- 基础功能不复杂；把用户选择保存位置、轨迹完整性和本地回放一起做完整，属于中等规模改动，主要在前端，无需重新计算模拟。
- 实时页面已有场景参数、任务、配送站和收到的帧；模拟结束后，时间轴缓存仍在当前页面中，可以作为导出数据源。
- 推荐流程为“模拟结束 → 保存本次轨迹 → 系统另存为对话框 → 用户选择文件夹和文件名 → 写出 JSON”；不自动打开对话框，也不自动保存。
- 应导出本次运行收到的全部帧及最终统计，而不是用户回看时选中的单帧。
- 当前 SSE 可能按 `frame_stride` 采样，且结束消息不包含最终快照；需要保留真实 Step、说明采样密度，并补齐最终帧，不能把收到的帧数当作总步数。
- 本地保存的文件不会自动进入服务器 `data/traces.json`。建议同时给回放页增加“打开本地轨迹”，直接选择保存的 JSON。
- 浏览器选择保存位置有兼容性与访问地址要求，不能承诺所有浏览器、普通 HTTP 远程 IP 都能直接弹出同样的保存窗口。
- 页面刷新、重新运行会清空现有缓存。这个功能应在运行前已经加载；不能靠刷新旧页面来追回刚结束运行的内存数据。

#### 1. 为什么可以复用现有数据

[src/dynamic_timeline.mjs](/data/zc/datasets/LaDe/viewer/src/dynamic_timeline.mjs) 的 `FrameTimeline.frames` 已保存本次页面连接收到的 payload，即使画面暂停或正在回看，后续帧仍会继续追加。

[src/dynamic_app.mjs](/data/zc/datasets/LaDe/viewer/src/dynamic_app.mjs) 在 `init` 事件中保留 `config`、`tasks`、`depots`、`regions` 等信息，在 `done` 中保留最终 `metrics`、结束原因和已运行步数。因此不需要重新调用 `build_delivery_sim.py` 跑一遍相同参数；重跑也不能替代保存这次运行的真实结果。

可将数据组织成与现有回放兼容的 JSON，包含：

- `config`、`tasks`、`depots`，以及可选的区域信息。
- `step_seconds`、结束时间、结束原因、已运行步数和最终 `metrics`。
- 所有接收到的 `frames`，逐帧保留真实 `step_index` 或原始帧编号。
- 可选的逐帧指标、近期事件与 LLM 调用信息；这些信息不必重复塞入每个位置才能完成基本地图回放。

导出时应从整段时间轴和最终结束消息取数据，不能直接使用正在显示历史画面的 `state.frame` 或历史 `state.metrics` 作为整场运行结果。

#### 2. 用户操作和保存位置

建议在实时页顶部增加“保存本次轨迹”：

1. 模拟未结束或没有轨迹时不可保存。
2. 收到正常 `done` 后允许点击，包括“任务全部完成”和“达到最大步数”两种结束原因；后者如实标注仍有任务未完成。
3. 用户点击后，先打开浏览器保存对话框，让用户选择文件夹和文件名。
4. 建议文件名包含城市、日期、无人机数、任务数和运行时间戳，降低同名覆盖概率。
5. 用户取消时停止保存，不自动改存下载目录。
6. 写入完成并关闭文件流后再显示成功；保存过程避免重复点击。普通重复保存仍由用户主动触发。

单个 JSON 文件推荐使用 `showSaveFilePicker()`：用户可以在另存为窗口同时选择目录及文件名。若明确需要“只选文件夹、文件名由系统生成”，可以使用 `showDirectoryPicker({mode: "readwrite"})`，但单文件导出不必要求整个目录的写权限。相关接口须由用户点击触发。参考：[Chrome File System Access 文档](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)、[MDN showDirectoryPicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)。

兼容性处理需要满足本次“用户选择文件夹”的要求：

- 使用 `showSaveFilePicker` 前检查浏览器是否提供该接口；它目前不是所有主流浏览器共同支持的能力，并要求安全上下文。参考：[MDN showSaveFilePicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker)。
- HTTPS 和浏览器访问的 localhost/回环地址符合相应安全上下文条件；直接访问普通 HTTP 远程 IP 不能一概认为可用。SSH 转发到本地 localhost 是可考虑的访问方式。参考：[MDN Secure contexts](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts)。
- 现有查询导出采用 Blob 加下载链接，只负责触发浏览器下载，没有选择目录的应用接口；不能直接复制该逻辑就宣称已实现强制选择保存文件夹。
- 不支持保存选择器时，应明确显示当前环境限制。若要提供普通下载作为替代，需要说明保存位置由浏览器设置决定，不能悄悄绕过用户选择位置的要求。

#### 3. 必须处理的帧完整性问题

[scripts/run_dynamic_sim.py](/data/zc/datasets/LaDe/viewer/scripts/run_dynamic_sim.py:107) 每步推进模拟，但仅在 `step % frame_stride == 0` 时发送帧。当前 `done` 发送最终指标、结束原因、总步数和结束时间，没有发送最终 frame。

例如运行了 8 步、推送间隔为每 3 步一帧时，前端收到的 `frame_index` 为 0、3、6，对应图谱 Step 1、4、7，实际结束位置却是 Step 8。

建议第一版明确保存“本次收到的采样轨迹 + 最终帧”：

- 在服务端结束事件中补充一次最终快照及真实结束 Step，前端导出时按 Step 去重或追加。
- 保留 `frame_stride` 和每帧的真实 Step；不能将数组第 N 项理解为第 N 步。
- 如果用户要求每一步都保存，应使用 `frame_stride=1`，或单独设计服务端保留完整轨迹的机制。浏览器无法凭收到的采样点补回未传输的中间状态。
- 终态补齐后，回放的最后画面和最终统计才能一致。

这项服务端补充只涉及结束数据的传输，不需要修改调度、派单或 Neo4j 查询逻辑。

#### 4. 保存后的文件如何回放

当前 [src/simulation_app.mjs](/data/zc/datasets/LaDe/viewer/src/simulation_app.mjs:63) 从服务器索引加载 JSON，没有读取用户电脑上自选文件的入口。

因此，建议在“轨迹回放”侧栏增加“打开本地轨迹”：用户选择刚保存的 JSON，前端校验结构后复用现有渲染逻辑。不需要将本地文件上传服务器，也不会自动改写服务器轨迹列表。

如果选择的保存目录在用户电脑上，服务端的 `build_trace_index.py` 无法扫描它；“本地另存为”和“服务端自动归档”应明确区分。

#### 5. 大规模数据的处理

普通演示规模可以直接导出 JSON。大型运行应避免把所有帧一次 `JSON.stringify()` 后又生成整份 Blob，造成额外内存峰值；可以在取得文件句柄后逐段写入配置和帧数组。

分段写入可以降低导出时的额外内存，但不能消除现有时间轴缓存本身的占用。是否需要分块缓存或更换轨迹格式，应根据实际运行规模单独决定。

浏览器保存对话框应在点击处理开始时调用，再处理、编码和写数据，避免长时间预处理导致用户激活状态失效。参考：[Chrome 保存文件示例](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)。

#### 6. 对已经结束的本次运行的说明

- 页面没刷新时，收到的帧仍可能在旧页面的内存里，但当前版本没有轨迹保存入口。
- 不能直接刷新加载新按钮，再期待原页面内存中的帧仍在；`resetRuntime()` 会清空时间轴。
- 后端在实时请求结束后会清理活动环境，目前没有一个可供结束后再次下载完整 trace 的接口。
- 若旧页面已经丢失缓存，是否能恢复只能看是否另有轨迹文件或可用的图谱记录；不能承诺凭当前前端自动找回。

### 后续建议

- 推荐实现“结束后手动另存为 JSON + 回放页打开本地轨迹”，默认保存到浏览器所在电脑。
- 保存动作严格由用户点击触发；不自动选目录，不自动保存，也不自动上传服务器。
- 第一版保存范围应明确为收到的轨迹帧并补齐终态；若需要每一步完整状态，再增加完整帧保留要求。
- 本轮为可行性评估，未启动实现或改动正在运行的服务。
