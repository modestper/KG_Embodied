### 任务背景

用户希望根据 `scripts/lade_llm_context_templates.py` 新建进程并发查询测试代码，保留源文件。该文件是模板库，现有实际线程压测入口为 `scripts/lade_llm_context_queries.py`，因此新增独立进程版入口并复用原查询与统计函数。

### 关键结论

- 新增入口为 `scripts/lade_llm_context_queries_process.py`，通过 `ProcessPoolExecutor` 和 `spawn` 实现多进程并发。
- 复用同一套 i0-i55 查询、查询包、参数构造、时间语义和统计逻辑，也支持原有自定义 JSON 查询。
- 并发单位仍为一次 drone 上下文查询包；包内查询依次执行。工作进程不与特定 drone 永久绑定，重复上下文任务的调度方式沿用线程版。
- 每个工作进程自行创建并复用一个 Driver，正常退出时关闭；Driver 和 Session 不通过进程队列传递。父进程统一写入日志。
- `--max-workers` 控制工作进程上限，默认等于输入的 drone 数。`--max-connection-pool-size` 改为每进程连接池上限，默认 1；它不是整个压测的连接总上限。
- 日志和汇总使用新的默认文件名，记录 `concurrency_mode`、`worker_pid`、进程启动方式和实际返回结果的进程数。
- 共 24 项测试通过，包含两个真实子进程和模拟 Driver；本次未运行真实 Neo4j 性能压测，不能据此判断多进程是否更快。

### 修改内容

- 新增 `scripts/lade_llm_context_queries_process.py`：独立进程压测入口；保留原命令行选项，新增进程元数据，使用独立的默认输出路径。
- 新增 `tests/lade_llm_context_queries_process_test.py`：真实进程离线测试、参数前置校验、命令行兼容性、查询列举与 dry-run 验证。
- 新增本总结。原模板文件与原线程入口均未修改。

默认输出文件为：

```text
data/lade_llm_context_process_query_logs.jsonl
data/lade_llm_context_process_contexts.jsonl
data/lade_llm_context_process_summary.json
```

逐条查询日志、上下文 JSONL 沿用原版的追加方式；汇总 JSON 沿用覆盖方式。不同实验可显式指定不同路径。

计时口径：

- `elapsed_ms`：沿用原版，从一次 `session.run()` 开始到结果消费完成，不含任务排队与进程通信。
- `total_elapsed_ms`：沿用原版的工作进程内整包上下文计时，不含任务在父进程排队、进程启动及返回结果的进程通信。
- `wall_ms`：从创建进程池前至进程池关闭后，包含进程启动、任务处理、进程通信、父进程日志写入和关闭开销。
- 如需从 Step 节点解析 `time_minute`，父进程先单独查询并关闭 Driver，该解析不计入 `wall_ms`，与原版预处理的位置一致。
- 实际有返回结果的工作进程数可能小于配置的进程数；进程上限不保证所有查询同时起跑。对比线程与进程时应同时查看整轮墙钟时间、吞吐和单查询分位数。

### 后续建议

现有线程版运行命令可直接将脚本名替换为 `scripts/lade_llm_context_queries_process.py`，保留原查询、drone、step、窗口、repeat 等参数。连接池参数需按每进程的含义设置。

下列示例在仓库根目录执行；将 `YOUR_RUN_ID`、`100` 和连接地址替换为实际实验值。未指定 `--time-minute` 时，时间类查询会按 step 自动读取对应时间。

```bash
./run_in_lade.sh python scripts/lade_llm_context_queries_process.py \
  --uri bolt://127.0.0.1:17687 \
  --database neo4j \
  --run-id YOUR_RUN_ID \
  --step-index 100 \
  --queries core \
  --drone-ids drone-1,drone-2,drone-3,drone-4 \
  --repeat 2 \
  --max-workers 4 \
  --max-connection-pool-size 1
```

若沿用原 100 drone 实验，请提供原先相同的 100 个 drone ID 并设置 `--max-workers 100`；不要只修改 worker 数而仍使用默认单个 drone。

比较线程版与进程版性能时，应固定数据库、查询组合、参数和数据版本，分别执行并保存到不同输出路径。当前实现与离线验证已完成，无需用户额外确认。
