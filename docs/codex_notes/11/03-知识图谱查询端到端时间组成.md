# 知识图谱查询端到端时间组成

### 任务背景

用户希望进一步分析知识图谱查询的端到端时间由哪些部分组成。本轮按当前前后端计时起止点解释，不执行实际查询或修改功能代码。

### 关键结论

- 当前页面最接近端到端时间的指标是 `browser_request_ms`：从发请求前到响应 JSON 解析完成，不包含结果表格构建和浏览器绘制。
- 查询链路有两段通信：浏览器与页面后端之间的 HTTP，以及页面后端与 Neo4j 之间的数据库通信。后者分布在准备和正式查询阶段中。
- 请求体校验、解析及响应 JSON 编码在 HTTP handler 中完成，位于 `backend_total_ms` 的测量范围之外，但包含在网页请求总耗时内。
- `backend_total_ms` 包含准备与校验、正式查询、事务清理及通知整理。准备包含实际的 EXPLAIN 数据库请求，不只是 Python 本地检查。
- 正式查询计时包含数据库通信、执行等待、驱动拉取、记录转换、大小检查及消费执行摘要。数据库报告耗时不能作为另一个独立阶段再次相加。
- 当前只有几个聚合指标，能得到某些综合差值，不能据此精确分离网络、数据库 CPU、驱动和前端各自占比。

### 修改内容

仅新增本解释文档。

#### 1. 当前网页端到端计时的组成

| 阶段 | 具体工作 | 对应现有指标 |
| --- | --- | --- |
| 浏览器请求准备 | 创建请求控制对象、设置等待时限、将查询和参数编码为 JSON、调用 fetch | 网页请求总耗时内部，未单独计时 |
| 请求发往后端 | 浏览器网络调度、连接建立或复用、HTTP 请求传输；具体开销取决于实际访问路径 | 网页请求总耗时内部，未单独计时 |
| 后端 HTTP 层接收和检查 | 请求路由、同源检查、Content-Type 和长度检查、读取请求体、解析 UTF-8 JSON | 网页请求总耗时内部，尚未进入后端处理总耗时 |
| 查询准备与只读校验 | Cypher 和参数检查、必要的 driver 和数据库连接准备、创建事务、提交 EXPLAIN 并消费摘要、确认只读类型 | `validation_ms`，包含在 `backend_total_ms` 中 |
| 正式查询和结果处理 | `tx.run()`、数据库工作和通信、逐条读取展示记录、值转换、结果大小检查、`consume()` 获取摘要 | `query_client_ms`，包含在 `backend_total_ms` 中 |
| 后端收尾 | 回滚只读事务、退出事务和 session、整理数据库通知及结果元信息 | 后端处理总耗时中除准备与查询外的剩余部分 |
| 后端响应编码和发送 | 将返回对象编码为 JSON/UTF-8、写响应头及响应体 | 网页请求总耗时内部，位于后端处理总耗时之外 |
| 响应传回浏览器 | HTTP 响应传输及浏览器相关调度 | 网页请求总耗时内部，未单独计时 |
| 浏览器解析 | 收取响应并执行 `response.json()`，至后续 JS 恢复执行和取计时值 | 网页请求总耗时的最后部分 |

可近似表示为：

```text
T网页请求
  = T浏览器请求准备
  + T请求传输及调度
  + T后端HTTP前置处理
  + T查询准备与校验
  + T正式查询和结果处理
  + T后端收尾
  + T响应编码与发送
  + T响应传输及调度
  + T浏览器JSON解析
```

以上用于解释范围，不意味着当前已经为每一项分别埋点。在流式结果读取中，数据库执行、传输和客户端处理也可能交替或部分重叠，不应将不同来源的时间不加区分地累加。

#### 2. 与页面五项指标的关系

```text
T后端总计 ≈ T准备与校验 + T后端查询 + T收尾
T网页请求 ≈ T后端总计 + T前后端外围开销
```

其中外围开销包含前端请求准备、HTTP、后端请求体解析、后端响应编码、浏览器解析和调度等；`T网页请求 - T后端总计` 不等于纯网络时间。

`T后端总计 - T准备与校验 - T后端查询` 可粗略反映事务清理和结果整理等收尾开销，受取点和三位小数舍入影响。

数据库报告耗时来自正式查询的 summary。它是服务器自身的统计口径，不包括前面的 EXPLAIN。不能再把它加进 `T后端查询`；两者的差值也不能简单称为网络延迟，客户端取回和转换结果等同样影响该差值。

#### 3. 示例

以下数字仅用于演示，不是实测：

| 指标 | 假设值 |
| --- | --- |
| 数据库报告耗时 | 30 ms |
| 后端查询耗时 | 50 ms |
| 准备与只读校验 | 20 ms |
| 后端处理总耗时 | 75 ms |
| 网页请求总耗时 | 100 ms |

可以近似解释为：

- 后端准备 20 ms、查询及取结果 50 ms、收尾约 5 ms，共 75 ms。
- 其余约 25 ms 用在网页请求计时范围内、后端查询服务计时范围之外的处理和通信中。
- 数据库报告的 30 ms 用于观察服务器侧统计，不再加到 100 ms 上。

#### 4. 真正“点击到表格显示”还包含什么

当前计时开始前，代码已经完成前端参数解析与检查、禁用按钮、清空旧表格和设置查询中提示。

当前计时结束后，代码才填写耗时卡片、创建结果表格 DOM、更新状态及历史列表，随后浏览器还需要布局和绘制。

因此完整的用户等待体验近似为：

```text
T点击至显示
  ≈ T事件响应及前端前置处理
  + T网页请求
  + T结果表格和历史DOM更新
  + T浏览器布局与绘制
```

现有页面没有测量这个完整值，不能用当前 `browser_request_ms` 宣称已经包含表格显示耗时。

### 后续建议

- 对比数据库查询表现时，保留数据库报告值和后端查询耗时；衡量接口响应体验时，关注网页请求总耗时，明确其不含渲染。
- 若后续需要性能占比图，应先补充 HTTP 层、JSON 编解码、数据库准备和客户端结果处理等分段埋点，再决定展示哪些百分比；现有五项数值不能直接做互斥占比饼图。
- 当前分析已完成，无需确认功能改动。
