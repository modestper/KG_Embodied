# 当前知识图谱关系属性核查

### 任务背景

用户希望确认当前知识图谱中的关系是否带有属性。检查了关系写入代码，并通过页面的现有只读查询接口读取当前连接实例中的实际关系。

### 关键结论

- 有属性，但并非所有关系都带属性。当前页面目标为 `bolt://127.0.0.1:17687`，实际查询数据库为 `neo4j`，环境运行标识为 `run1027_process`。
- 实测该运行 `drone-1` 的 `ASSIGNED` 关系带有 `time_minute`、`time`、`active`、`completed_time_minute`、`completed_time`。
- 实测 `COMPLETED` 关系带有 `time_minute`、`time`、`late`；`IN_RUN` 的属性为空对象 `{}`。
- 写入代码还为 `CARRYING` 设置取货时间和有效状态，为 `ASSISTS`、`HANDOVER_TO`、`TAKES_OVER` 设置互助相关属性；本次有限样本没有逐一验证这些类型是否都在当前运行中出现。
- 本次只抽样读取一个运行、一架无人机的最多 20 条关系，不是全库关系属性普查。

### 修改内容

仅新增本文档，无功能代码或数据库修改。

实际使用的抽样查询：

```cypher
MATCH (a:Drone {run_id: $run_id, id: 'drone-1'})-[r]->(b)
WHERE type(r) IN [
  'ASSIGNED', 'CARRYING', 'COMPLETED',
  'ASSISTS', 'HANDOVER_TO', 'TAKES_OVER', 'IN_RUN'
]
RETURN type(r) AS relationship_type, properties(r) AS properties
LIMIT 20
```

参数：`{"run_id":"run1027_process"}`。

实际示例：某条 `ASSIGNED` 的 `time` 为 `08:09:00`、`active` 为 `false`、`completed_time` 为 `08:22:00`；对应抽样中一条 `COMPLETED` 的 `time` 为 `08:22:00`、`late` 为 `false`。

字段含义：`time`/`time_minute` 是相应关系记录的模拟时间，不是数据库写入的墙钟时间；`active` 表示该关系当前是否有效；`late` 表示是否迟到完成。`completed_time*` 表示完成时记录的时间。互助关系的 `reason` 表示原因，`updated_at` 在当前代码中也是模拟分钟值，不能按实际日期时间解释。

### 后续建议

- 在查询窗口中使用 `properties(r)` 查看关系属性、`keys(r)` 查看属性名；节点的属性与关系的属性分开存储。
- 查看其他类型时可将关系类型直接限定为 `CARRYING` 或 `ASSISTS`，避免 LIMIT 返回的样本集中在前几个类型。
- 无需确认功能改动；本轮核查已完成。
