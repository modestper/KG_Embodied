### 任务背景

用户希望回到建立 AgentState 复合索引之前的状态，再测试查询是否恢复到原始耗时。本次只说明可重复的对照方法，不对现有 Neo4j 数据库作 schema 变更。

### 关键结论

- 按上下文把“没有检索的版本”理解为“没有索引的版本”；若指另一个程序版本，需要另行定位代码版本。
- 三组新增 RANGE 索引仅针对 AgentState；i0/i3 本来就从 Drone 的 NodeByLabelScan 开始，建索引前后它们的算子及访问条件一致。只验证 i0/i3 时不需要删除三组 AgentState 索引。
- 旧 i0 平均约 11 ms 来自 12 条模板混合执行；新的 114 ms 来自 100 个 drone 仅执行 i0，每秒约 591 次。要检验旧结论，必须复用原 `--queries`、drone IDs、repeat、max_workers、连接池、日志和数据库负载，而不能只删除索引。
- 不改变数据库的方案：复制查询模板到独立文件，对 AgentState 访问分支加入 `USING SCAN variable:AgentState`，并用 EXPLAIN 逐条确认算子。该方法复现标签扫描访问路径，但并不移除索引的缓存与后台写入维护开销，不等同于真实无索引数据库。
- 真实“数据库无这三组索引”可用 Neo4j Browser 按索引名称 DROP INDEX，之后通过 SHOW INDEXES 核对，复测后按原 CREATE 命令重新建立并等待 ONLINE。DROP INDEX 是整个数据库级别变更，会影响其他查询和正在运行的实验；本轮未执行。
- 当前 `simulation/knowledge.py` 在 `KG_RECORD_AGENT_STATE=1` 时默认 `KG_AUTO_CREATE_INDEXES=1`；新仿真进程启动会重建缺失索引。基线运行必须在其启动环境设置 `KG_AUTO_CREATE_INDEXES=0`，修改当前 shell 环境不会改变已运行进程的配置。
