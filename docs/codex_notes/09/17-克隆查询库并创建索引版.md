### 任务背景

用户希望把当前 Docker volume `lade-query-neo4j-data` 完整克隆为 `lade-query-neo4j-data-index`，并启动一个独立的 Neo4j 容器，在副本中建立三组 AgentState 索引，用于有索引/无索引性能对照。

### 关键结论

- 已新增 `scripts/clone_neo4j_query_volume.sh`。
- 脚本默认只预览，必须传 `--apply` 才会改变 Docker 状态。
- 源查询容器默认为 `lade-query-neo4j`，目标容器默认为 `lade-query-neo4j-index`。
- 源 volume 为 `lade-query-neo4j-data`，目标 volume 为 `lade-query-neo4j-data-index`。
- 目标 HTTP/Bolt 端口默认为 `47474/47687`，源查询库仍使用 `37474/37687`。
- 文件级一致克隆需要短暂停止源查询容器；脚本不会停止原始数据容器 `neo4j`。
- 克隆 `/data` 会同时复制节点、关系、schema、事务状态和认证库；目标用户名、密码与当前源查询库相同。
- 使用 `--create-agent-state-indexes` 后，脚本会在目标副本创建三组索引并等待全部 `ONLINE`。

### 对象关系

```text
无索引查询库
  容器: lade-query-neo4j
  volume: lade-query-neo4j-data
  HTTP: 37474
  Bolt: 37687

索引版查询库
  容器: lade-query-neo4j-index
  volume: lade-query-neo4j-data-index
  HTTP: 47474
  Bolt: 47687
```

两个容器中的 database 名仍然都是 `neo4j`。`lade-query-neo4j-data-index` 是 Docker volume 名，不是 Neo4j 内部 database 名。

### 第五步：正式克隆并建立索引

```bash
bash scripts/clone_neo4j_query_volume.sh \
  --apply \
  --create-agent-state-indexes
```

脚本执行顺序：

```text
拒绝覆盖任何同名目标
  -> 创建空目标 volume
  -> 记录源容器是否正在运行
  -> 停止 lade-query-neo4j
  -> 只读挂载源 volume
  -> 完整复制到目标 volume
  -> 恢复 lade-query-neo4j
  -> 使用相同 image 启动 lade-query-neo4j-index
  -> 等待目标 Bolt 可连接
  -> 创建三组 AgentState 索引
  -> CALL db.awaitIndexes(...)
  -> 输出索引状态
```

创建的索引为：

```cypher
CREATE INDEX lade_agent_state_run_drone_step IF NOT EXISTS
FOR (n:AgentState) ON (n.run_id, n.drone_id, n.step_index);

CREATE INDEX lade_agent_state_run_region_step IF NOT EXISTS
FOR (n:AgentState) ON (n.run_id, n.region_id, n.step_index);

CREATE INDEX lade_agent_state_run_step IF NOT EXISTS
FOR (n:AgentState) ON (n.run_id, n.step_index);
```

### 为什么需要暂停源查询容器

该方案复制的是 Neo4j `/data` 底层文件，而不是通过 Bolt 逐条读取节点。在 Neo4j 运行且持续修改 store/事务日志时直接复制，文件可能处于不同时间点。

因此脚本只在复制期间停止：

```text
lade-query-neo4j
```

它不会停止：

```text
neo4j
zxxzy-manipmob-ssd-neo4j
```

如果源查询容器原本处于运行状态，脚本复制后会重新启动；如果原本已停止，脚本不会擅自启动。

脚本设置了退出 trap。如果复制阶段失败，会尝试恢复原本正在运行的源查询容器。

### 为什么不用 Python 驱动再次复制

这里的目标是得到尽可能一致的 A/B 数据副本。volume 克隆能够原样保留：

- 节点与属性；
- 关系、方向和属性；
- 当前约束和索引状态；
- Neo4j database metadata；
- 认证库。

Python 子图迁移适合只复制部分 run；volume 克隆适合完整复制同一个查询库。由于当前 `lade-query-neo4j-data` 已经只包含目标数据，volume 克隆更直接。

### 性能对照注意事项

- 两个容器位于同一宿主机，不要同时压测，否则会竞争 CPU、内存和磁盘。
- 新启动的索引版 page cache 是冷的；两个版本应采用相同预热流程。
- 两个容器使用同一 image，但脚本没有复制源容器的 `/logs`、插件目录或额外 Docker 资源限制。
- 如果源查询容器配置过特殊 heap/page cache 或 Docker CPU/内存限制，需要在目标容器上使用相同设置后再做严格比较。
- 为每个版本使用独立日志路径，例如 `data/index_experiments/no_index/` 和 `data/index_experiments/index/`。

### 失败时的处理

脚本拒绝覆盖已有目标。如果中途失败，可能留下：

- 空或部分复制的 `lade-query-neo4j-data-index`；
- 尚未成功启动的目标容器；
- 已启动但索引创建失败的目标容器。

首先检查：

```bash
sudo docker ps -a --filter name=lade-query-neo4j-index
sudo docker volume inspect lade-query-neo4j-data-index
sudo docker logs --tail 100 lade-query-neo4j-index
```

不要直接重新运行 `--apply`，因为脚本会拒绝覆盖。如果确认目标副本没有任何需要保留的数据，才可以删除目标容器和目标 volume 后重试：

```bash
sudo docker rm -f lade-query-neo4j-index
sudo docker volume rm lade-query-neo4j-data-index
```

这些删除命令不可恢复，但只针对明确命名的目标副本；不要对源容器或源 volume 使用。
