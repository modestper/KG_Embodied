# 仿真启动自动索引

### 任务背景

将 `AgentState` 查询索引的检查和创建整合到仿真启动过程。使用 Neo4j 并记录每个 step 的 agent 状态时，启动阶段先复用已有等价索引；缺少索引时创建并等待 `ONLINE`，之后才进入仿真写入。后续新增节点的索引条目由 Neo4j 自动维护。

### 关键结论

- 自动初始化集中在 `Neo4jKnowledgeStore`，local 和 Ray 仿真共用该入口。
- 仅在 `KG_BACKEND=neo4j` 且 `KG_RECORD_AGENT_STATE=1` 时默认启用，不影响内存后端和不记录 AgentState 的实验。
- 通过 `SHOW INDEXES` 比较标签、索引类型和完整属性序列；不同名称但定义相同的 RANGE 索引也会复用。
- 缺失时创建三组索引：`(run_id, drone_id, step_index)`、`(run_id, region_id, step_index)`、`(run_id, step_index)`。
- 索引达到 `ONLINE` 后构造函数才返回；`FAILED`、名称冲突或等待超时会阻止仿真开始并给出明确错误。
- 可用 `KG_AUTO_CREATE_INDEXES=0` 关闭自动处理，等待上限由 `KG_INDEX_WAIT_TIMEOUT_SECONDS` 设置，默认 600 秒。
- 真实 Neo4j 检查成功复用此前已经存在的三个索引，没有创建重复定义。

### 后续建议

- 正常情况下无需新增启动参数；现有 `KG_BACKEND=neo4j KG_RECORD_AGENT_STATE=1` 会默认启用。
- 首次在大型旧数据库上建立缺失索引可能超过 600 秒，可设置更大的 `KG_INDEX_WAIT_TIMEOUT_SECONDS`。
- 基线实验如需明确禁止 schema 自动变化，可设置 `KG_AUTO_CREATE_INDEXES=0`。
- 三组索引已存在的当前数据库，后续启动只进行轻量检查并立即复用；不会再次扫描 164 万个 AgentState 建索引。
